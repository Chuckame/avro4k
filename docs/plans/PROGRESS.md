| 2026-09-23 | C3 superseded | **Shared mutable state in a singleton is the wrong home for a per-operation memo.** Raised by the user: C3's cache was one global slot shared by every thread and every `Avro` instance, so it only hit while one collection serializer repeated; alternating collection fields, top-level collections (`serializer<List<Foo>>()` is fresh per call) and concurrent decoding of different types missed every time, at two allocations per miss. | 2026-09-23 | C3 superseded | **Rule for M3/C1 and every later unit:** (1) *shared* caches — singleton or `Avro` instance, read by all threads — must be immutable once published or CAS-based, and written rarely (`WeakIdentityKeyCache`, C2's copy-on-write memo); (2) *mutable per-operation* state (last-seen memos, scratch buffers) lives on the decoder/encoder of one call, never in a shared object — C1's single decoder per call is its home; (3) anything fitting neither is designed away, as here. |
| 2026-09-23 | C3 superseded | **The block loop had no test at all.** avro4k's encoder always writes a single block, so every existing round trip passed through the loop exactly once; a loop reading only the first block would have passed the whole suite. | 2026-09-23 | B6 follow-up | **An unmeasured "obviously fine" choice was wrong, and only a micro-benchmark could show it.** B6 replaced the middleware's `IdentityHashMap`s with a linear `===` scan, expecting parity at ≤5 entries; the end-to-end A/B was neutral. Asked to justify it, a dedicated micro-benchmark showed the scan was **2× slower than the map and 3× slower than a `when` chain** (miss: 2.39 / 1.24 / 0.75 ns) and loses at every size up to 32 — no crossover. Switched to `when { x === A -> … }` over static finals (JIT-constant compares, platform-neutral), with a parity test guarding the serializer/descriptor chains against drifting. Lesson: an end-to-end "neutral" only bounds a change to ~10% of the whole path; a ~1 ns step inside a ~30 ns element is invisible there. |

## Measured numbers

**The baseline is `benchmark/README.md` → "Results — M0 baseline"** (2026-09-20, Apple M2 Pro,
OpenJDK 21.0.11). Every later claim is measured against it, and numbers are committed alongside the
change that produced them.

The pre-M0 table that used to sit here (`simple` +15%/+25%, `complex` −7%/−17%, `lists` +39%/−15%)
has been **deleted rather than kept for reference**: it was produced on different hardware, with
dead-code elimination inflating the read side, with harness allocation inside the measured write,
and against an Apache read path that does not run at all on this JDK. Keeping it would invite
false comparisons.

Headline, post-M0: avro4k **write** leads Apache by +71…79% on `complex` at every size. avro4k
**read** allocates 5.7× what write does — decode is where the work is.
