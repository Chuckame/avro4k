# A5 — per-library models + equivalence gate

**Outcome:** done
**Commit:** `6689f2e`

## What changed

### A model per library

`benchmark/src/main/kotlin/com/github/avrokotlin/benchmark/internal/` now holds three model trees:

| Package | Owner | Shape |
|---|---|---|
| `internal/` | **avro4k — the model under test** | unchanged, except that the Jackson annotations that used to sit on it moved out |
| `internal/apache/` | Apache `ReflectData` | same fields, same types, mutable + no-arg constructor |
| `internal/jackson/` | Jackson | `complex` only; `simple` and `lists` reuse avro4k's model as-is |

avro4k's model kept **all** of its type coverage: `Byte`, `Short`, `Char`, `BigDecimal`, `ByteArray`,
`Array<String>`, `LongArray`, `List<String?>`, the sealed `Partner`, `LocalDate`, `Instant`. Nothing
was weakened to make another library agree.

Apache's copy differs from it in exactly three ways, each forced by `ReflectData`:

1. **Mutable properties + a no-arg constructor.** `ReflectData` instantiates with the no-arg
   constructor and populates by reflective field writes.
2. **`@AvroSchema` on `gender` and `tags`.** `ReflectData` infers `int` + `java-class:
   java.lang.Character` for a `Char` where avro4k emits `int` + `logicalType: char`, and erases
   `List<String?>` to `array of string`. Both are pinned by hand to avro4k's shape.
3. **`@Union` on `partner`,** since a Kotlin sealed interface has no Avro equivalent and the branch
   *order* is part of the wire format.

`Byte`/`Short` were **not** widened to `Int`: `ReflectData` annotates them `java-class:
java.lang.Byte` and narrows the decoded `Integer` itself, so the model stays faithful.

Jackson's copy of `complex` exists for one reason, `Partner` — see "What was rejected".

### The gate

- `internal/SchemaEquivalence.kt` — structural schema comparison with per-path exemptions.
- `internal/ByteEquivalence.kt` — byte identity, reporting the first differing offset with a 12-byte
  hex window either side.
- `internal/EquivalenceGate.kt` — runs, per library: same schema, same bytes, **and** "nothing lost on
  read" (decode avro4k's bytes with that library, re-encode, compare). The third check is not in the
  brief but the whole unit is about the read side: without it a library could decode half a record
  and look like the winner.
- `internal/WorkloadEquivalence.kt` — the per-workload wiring, built from the same
  `ApacheAvro.reflectData()` / `JacksonAvro.mapper()` factories the benchmarks use, so what is
  verified is what is measured.

`SerializationBenchmark`, `SerializationSimpleBenchmark` and `SerializationListsBenchmark` call their
workload's gate from `@Setup`, before `setup()` and before any data is encoded. It runs for every
benchmark class (so the Apache benchmark also proves Jackson's side), once per trial, and throws.

The base classes' `@Setup` also changed order: the data is generated **first**, so `setup()` can
convert it to the library's own model there. No conversion happens in a measured method.

### What the schema comparison catches, and what it does not

`Schema.equals` is unusable (it compares reflection hints and field defaults, which two byte-identical
encoders never agree on) and `SchemaNormalization.toParsingForm` is worse (it **strips logical types**,
so `decimal` decaying to plain `bytes` would compare equal). So the comparison is a hand-written
structural walk.

**Catches:** a different `Schema.Type` anywhere; a different `logicalType` — compared as the **raw
property string**, not via `Schema.getLogicalType()`, so avro4k's unregistered `char` is compared too;
record field **count, names and order**; enum symbols and their order, and the enum default; `fixed`
size; union branch count and **order**; named-type simple names, and namespaces after an explicitly
declared alias; every other schema and field property.

**Does not catch:** field **defaults** (avro4k emits them, `ReflectData` does not; they do not affect
the encoding when writer and reader schema are the same, which they always are here); the four
object-mapping hints `java-class`, `java-key-class`, `java-element-class`, `avro.java.string`; `doc`
and `aliases`; a namespace difference that is *declared* in the alias map (each library needs its own
package, so the record full names cannot be identical — any **undeclared** namespace difference still
fails).

Everything in that second list is covered by the byte half of the gate: none of it can change the wire
format without a differing offset showing up.

A declared exemption that stops matching anything **fails the gate** as a "stale exemption", so an
exemption cannot outlive the limitation that justified it.

## What was measured

Machine: the A4 machine (Apple M2 Pro, macOS 26.6.2, OpenJDK 21.0.11, Apache Avro 1.12.1).
All figures `-f 1`, the classes' own 5×1s warmup / 5×3s measurement, `clientCount=1`, so they are
**indicative, not a baseline** — A8 re-captures the real one.

### Byte identity

| Workload | avro4k | Apache | Jackson |
|---|---|---|---|
| `complex` | ✅ | ✅ write **and** read/re-encode | ⚠️ decoded-data equality only (map entry order) |
| `simple` | ✅ | ✅ | ✅ |
| `lists` | ✅ | ✅ | ✅ |

Schema equivalence holds everywhere, with four declared exemptions on `jackson/complex` and none
anywhere else.

### The nine benchmarks that used to vanish

All nine now produce numbers, `<failure>` count zero:
`complex.ApacheAvroReflectBenchmark.read`, `simple.ApacheAvroReflectSimpleBenchmark.read` and
`complex.JacksonAvroBenchmark.read`, at all three parameter values each.

### Effect on the Apache numbers (this moves the baseline)

`complex` @ 1 client, ops/s:

| Configuration | write | read |
|---|---:|---:|
| Pre-A5 (replica: `ReflectData.get()`, avro4k's schema, avro4k's model) | 363,890 | _did not run_ |
| A5 | 358,314 ± 3,711 | 298,365 ± 14,909 |
| avro4k, same run | 609,769 ± 36,035 | ~349,000 |

Apache's **write** is within 2% of the pre-A5 configuration, so A5 does not distort the comparison it
replaces — and Apache's **read** exists for the first time.

Two things had to be fixed to get there, and both are worth knowing:

1. **Two `ReflectData` instances cost 40% of Apache's write throughput.** `ReflectData.ACCESSOR_CACHE`
   is **static** and maps schema → field accessors in a `WeakHashMap`. Two instances build two
   equal-but-distinct schema objects for the same class; they land in the same hash bucket, and every
   record write then pays a deep `Schema.equals` to walk past the first one. Measured 358k → 219k.
   `ApacheAvro.reflectData()` therefore returns **one shared, configured-once instance** — which is
   also what makes the `@Setup` mutation of global state idempotent, as the unit brief asked.
2. **`ReflectData.getCustomEncoding` is asked for a custom encoding on every datum**, from a
   `ConcurrentHashMap<Schema, …>` whose key comparison is `Schema.equals` → `JsonProperties.propsEqual`
   → a full property-map comparison. With a property-carrying schema (which `ReflectData`'s own schema
   is) the lookups collide.

## What was rejected, and why

- **Keeping avro4k's schema for Apache.** `ReflectData` maps a decoded value back onto a Java field
  using the `java-class` hints *in the schema*: without them it hands a `GenericData$Array` to an
  `Array<String>` field and an `Integer` to a `Byte` one. That is the real cause of the two
  `IllegalArgumentException: Can not set final … field …` failures — **not** Kotlin `val` finality, as
  A4's note concluded. `java.lang.reflect.Field.set` builds that message from the field's modifiers,
  so "final" is descriptive, not the reason; the exception type (`IllegalArgumentException`, not
  `IllegalAccessException`) says it is a type mismatch. The `lists` workload read fine on `val`s all
  along, which is the other half of the proof. **A4's diagnosis in `notes/a4.md` and in
  `benchmark/README.md` is wrong on this point and should be corrected when the README is rewritten.**
- **An identity-keyed cache in front of `getCustomEncoding`.** It is worth **+69% on Apache's `complex`
  write** (358k → 606k ops/s, putting Apache level with avro4k). Rejected: no Apache user gets it, so
  measuring it would report Apache as faster than it is. Broadening Apache legitimately is A6/A7's job.
  Recorded in `ApacheAvro.kt` as a deliberate non-override so nobody has to rediscover it.
- **Renaming the Apache model's fields to control ordering.** `ReflectData.getFields` sorts fields
  alphabetically, and Avro's encoding is positional, so its inferred schema can never match avro4k's
  field order. The alternative was prefixing every Java field name (`f01id`) and restoring the real
  name with `@AvroName`. Instead `DeclarationOrderReflectData` undoes the sort, using the **model's own
  declaration order** — not avro4k's schema — so the order is still *verified* by the gate rather than
  imposed by it.
- **Declaring Jackson's `partner` as `Partner?` with `@Union`.** Jackson has exactly two triggers for
  reading an Avro union polymorphically (`AvroAnnotationIntrospector._findTypeResolver`): an
  `org.apache.avro.reflect.@Union` on the type, or a declared type of `java.lang.Object`. The first one
  installs `AvroTypeResolverBuilder` correctly — confirmed by introspection, applied as a **mix-in** so
  avro4k's model stayed clean — but `AvroTypeDeserializer` then finds no native type id on the parser
  and falls back to the abstract base type, failing identically. Only `Any?` works, via
  `AvroUntypedDeserializer`. Adding a Jackson-local copy of the branch classes also fails: both
  `AvroWriteContext.resolveUnionIndex` and `AvroTypeIdResolver` key on the **class full name**, which
  must be the one the canonical schema declares — so the branch classes are avro4k's own.
- **Excluding Jackson from `complex`.** Not necessary: only the map-entry order differs, and the gate
  still proves the two encodings decode to identical data. See the exemption below.

### Declared exemptions (the complete list)

**`jackson/complex`, byte identity → decoded-data equality.** `jackson-dataformat-avro` buffers every
Avro map into a `java.util.HashMap` (`ser.MapWriteContext._data`), losing the insertion order avro4k
writes. There is no setting for it. `Client.map` has ten entries, so every `complex` encoding differs;
the gate falls back to comparing the decoded data, which still proves every value is identical and
narrows the difference to framing or map entry order. `simple` and `lists` have no map and stay under
strict byte identity.

**`jackson/complex`, four schema paths.** These are limits of `AvroMapper.schemaFor`, not of what
Jackson encodes — it is handed avro4k's schema and writes exactly those bytes:

| Path | Why |
|---|---|
| `Clients.clients[].gender<1>` | Jackson has no `char` logical type; it generates a plain `int` |
| `Clients.clients[].registered<1>` | `AvroJavaTimeModule` writes a `LocalDate` as an `int` but generates no `date` logical type |
| `Clients.clients[].tags[]` | `List<String?>` erases to an array of non-null `string` |
| `Clients.clients[].partner` | the property is `Any?`, so the generated schema has `java.lang.Object` where avro4k has three branches (this also hides the branches' missing `timestamp-millis`, which Jackson does not generate either) |

Nothing else is exempt anywhere.

## Things a future session would otherwise rediscover the hard way

- **`ReflectData` sorts record fields alphabetically** (`getFields` → `Arrays.sort`). Any schema it
  infers is in alphabetical order, which for Avro's positional encoding means different bytes.
- **`Conversions.DecimalConversion()` must not be registered here.** `ReflectData.createSchema`
  consults registered conversions *before* it considers a stringable class, and
  `DecimalConversion.getRecommendedSchema()` throws `No recommended schema for decimal (scale is
  required)` — so registering it makes schema inference for `BigDecimal` fail outright. The `uuid`
  conversion is gone too: no benchmark schema carries either logical type.
- **`@Stringable` on the `BigDecimal` field, not plain inference.** Without it `ReflectData` emits
  `{"type":"string","java-class":"java.math.BigDecimal"}` and *reading* that trips Avro's
  `SERIALIZABLE_CLASSES` guard: `Forbidden java.math.BigDecimal! This class is not trusted…`. The
  annotation pins the clean `"string"` avro4k emits and routes the value through the accessor's
  stringable path (`toString()` / `new BigDecimal(String)`), which is the same work avro4k's
  `@AvroStringable` does.
- **`GenericData.newMap` returns a `HashMap`,** so a decoded Avro map comes back in hash order. avro4k
  decodes into a `LinkedHashMap`. `DeclarationOrderReflectData` overrides `newMap` to match — which
  costs Apache slightly rather than helping it, and is what makes the read/re-encode check possible.
- **Jackson decodes the `Stranger` enum branch of the union to its symbol `String`,** not to the enum
  constant. Re-encoding reproduces avro4k's bytes exactly, so nothing is lost on the wire, but
  Jackson's decoded value for that one branch is less typed than avro4k's or Apache's.
- **Jackson's `complex` write was never byte-identical to avro4k's.** Nothing checked before A5, and
  the map-order difference has presumably been there since the benchmark was written.
