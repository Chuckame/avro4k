### Fixes and changes to the kmp model

1. **Cycle-safe `equals` was broken on kmp.** It put a fresh `SeenPair` into an *identity* set. A fresh pair is
   never identical to an earlier one, so the cycle check never fired. Comparing two distinct instances of a
   recursive schema recursed until stack overflow, on every platform. Now the set is a
   `HashSet<SeenPair>`. `SeenPair` compares by identity and hashes through the records' O(1) hash. Tests:
   `recursiveSchemasParsedTwiceAreEqualWithSameHashCode` and `mutuallyRecursiveSchemasAreEqual`, both run on
   jvm, js and native.
2. **`hashCode` needs no cycle tracking any more.** `RecordSchema.hashCode()` is `name.hashCode()`, and
   `IdentitySet` is used only by `toString`. See the hashCode decision below.
3. `LockableList` changes:
   - It is now `@InternalAvro4kApi public`, because apache-interop builds recursive records with it.
   - `onLock` is an internal nullable property.
   - `add(element)` is still overridden, because `AbstractMutableList.add` reads `size`, which is illegal before
     `lock()`.
4. Field-default validation treats a record that is still being built (unlocked fields) as valid. Before, a
   default that went through an enclosing recursive record threw `Cannot access a non-locked list`.
5. JSON parser:
   - A short name is looked up in the current namespace first, then in the null namespace, as Apache does.
   - `fromJsonString` is public.
6. **JSON serializer bug:** take a null-namespace record nested in a namespaced one. Its fields were serialized
   with the *parent's* namespace as context, while the JSON declares `"namespace": ""`. A type in the parent's
   namespace nested inside it lost its namespace on re-parse. Fixed to use the record's own namespace
   (`recordInNullNamespaceNestedInNamespacedRecordRoundTrips`).
7. Field `order`: the JSON parser already kept it as a field prop. `toAvro4k()` now does the same when the order
   is not ascending. kotlin-generator skips `order` when it emits `@AvroProp`, because Apache reserves it and
   `Field.addProp("order")` throws. Generated code is unchanged: `order` was dropped before too.
8. `toAvro4k()` defaults: the raw default JSON node (`Accessor.defaultValue(field)`) is converted with its schema.
   Only numbers are converted: an integer literal for a `float`/`double` becomes `36.0`, like
   `Field.defaultVal()`, which keeps kotlin-generator's output byte-identical. `defaultVal()` itself is **not**
   used because it is lossy:
   - It returns `null` for core-generated int defaults, which are `BigIntegerNode`s.
   - It returns `[null,null]` for a `List<Long>` default.

## Decisions on scope points 6, 7 and 10

- **(6) `kotlinx-serialization-json` is `api` in `commonMain`.** The public API exposes `JsonElement`:
  - `props: Map<String, JsonElement>`;
  - `Field.defaultValue: JsonElement?`;
  - `toJsonElement` / `fromJsonElement`.
- **(7) kotest assertions are in `commonTest`.** Maven Central shows `kotest-assertions-core-androidnativearm32` for
  6.2.1 through 6.2.5 (6.2.0 returns 404). The 6.2.5 `.module` lists every variant of our matrix. Bumped to
  6.2.5, the latest patch. commonTest uses `kotlin.test.@Test` with kotest matchers.
- **(10) `RecordSchema.hashCode()` is name-based rather than cached.** Equal records always have equal names, so
  this is consistent with `equals`. It is O(1), allocates nothing, never walks the fields (so it is cycle-free),
  and stays valid before the `LockableList` is locked and even if a caller mutates the list they passed. A cached
  structural hash was rejected for three reasons:
  - It cannot be computed before `lock()`: `size` throws.
  - It goes stale if a plain mutable list is passed and later mutated.
  - kmp's structural hash was not even sound: bisimilar cyclic graphs, which `equals` accepts, hash differently.

  `Array`, `Map` and `Union` hashes are shallow structural and stop at records. Test:
  `recordHashCodeDoesNotReadFieldsSoItWorksWhileTheRecordIsBeingBuilt`, which hashes before `lock()`, checks that
  the hash is the same after, and uses the record in a `Set`.

## Round-trip coverage (`apache-interop/src/test/.../AvroSchemaApacheInteropTest.kt`)

- **105 schema files:** the 51 in `core/src/jvmTest/resources` and 54 of the 55 in
  `kotlin-generator/src/test/resources`. The excluded one is
  `types-across-multiple-files-fail/type-record-without-namespace.avsc`, which references an undefined type on
  purpose. Files that reference types in other files of their directory are parsed with a shared `Schema.Parser`
  and a shared `knownNamedTypes`.
- **Four checks per file:**
  - Apache → avro4k → Apache `==`.
  - Apache → avro4k → Apache → avro4k `==`.
  - JSON-parsed avro4k → Apache → avro4k `==`.
  - JSON-parsed avro4k `==` the Apache conversion.
- **Ten schemas generated by avro4k.** `Everything` covers:
  - every primitive, bytes and fixed;
  - decimal, uuid, date, time, timestamp and instant logical types;
  - nullable fields and defaults (int, float, list, enum, null);
  - lists, sets, maps and nested collections;
  - enums with `@AvroEnumDefault`;
  - sealed unions (nullable, and across namespaces);
  - recursive `Node` / `Tree`;
  - record and field aliases, docs, and string and JSON props;
  - value classes and `@AvroStringable`.

  Plus `Node`, `Tree`, `Shape`, `Suit`, `Wrapper`, list/map of records, `String?` and `Int`.
- Also tested: recursive identity is kept, `order` round-trips, and the known exceptions are still exceptions.

**What does not round-trip under Apache `Schema.equals`.** Neither case is a model bug. In both, Apache compares
default JSON nodes by node **type**.

1. **Integer literal as the default of a float or double.** Only
   `kotlin-generator/.../record-as-default.avsc` hits this (`"floatField": 36` in a record default).
   `toAvro4k()` renders it `36.0` on purpose, because generated code depends on it. Apache sees `IntNode(36)` ≠
   `DoubleNode(36.0)`. The test asserts equality against the re-parsed normalized schema, and checks that the
   avro4k side is stable.
2. **Schemas built by core's `Avro.schema()`.** Core builds int defaults as `BigIntegerNode`; the parser builds
   `IntNode`. The JSON text is identical, but Apache `equals` is false. So generated schemas are compared on
   `toString()` and against their re-parsed form. A test pins the `BigIntegerNode` fact.

## Perf-caveat audit

- **No core hot path uses `AvroSchema` in M2.** Grepping core's `jvmMain`, confluent and benchmark finds no
  reference to it; their only `AvroSchema` hits are Confluent's and Jackson's classes of the same name. Encoders
  and decoders still run on Apache `Schema`. `toAvro4k` / `toApacheSchema` are called only by kotlin-generator,
  once per codegen.
- **Must be identity-keyed when B3 moves them to `AvroSchema` keys.** All three are
  `WeakKeyCache<Schema, …>`, which uses `hashCode` plus `equals`:
  - `RecordResolver.fieldCache`: the decoder hot path, keyed by writer schema.
  - `AnySerializer.decodingCache`.
  - `AvroSingleObject.fingerprintCache`.

  On `AvroSchema`, `equals` is structural and walks the whole schema whenever two instances are equal but
  distinct. Every override starts with `this === other`, so a hit on the same instance is cheap. Distinct but
  equal instances cost a full walk. Use B6's `WeakIdentityKeyCache`.
- The same rule applies to any `Map`/`Set` keyed by `AvroSchema` in B3's schema visitors or resolvers.
  `Avro.schemaCache` is keyed by `SerialDescriptor`, not by schema, so it is unaffected.
- B6 must also add an identity cache inside `toAvro4k` / `toApacheSchema` before any M3 path calls them. Both walk
  the whole schema, and `toApacheSchema` also serializes and parses JSON.

## What was rejected, and why

- **kmp's `Schema.toAvro4k()` via `SchemaFormatter` JSON:** it changes kotlin-generator output (`36` vs `36.0`),
  and it is slower.
- **`Field.defaultVal()` as the default source:** it is lossy (point 8 above).
- **A cached structural `RecordSchema` hash:** point 10 above.
- **Dropping `browser()` from JS:** not needed. `jsBrowserTest` passes locally with Chrome.

## Follow-ups

- **B6:**
  - Add an identity cache to `toAvro4k` / `toApacheSchema`.
  - Use `WeakIdentityKeyCache` for the three schema-keyed caches listed above once their keys become
    `AvroSchema`.
- **M3 / B3 API polish** (the model is public now, but no caller outside avro4k's own modules exists yet):
  - `FixedSchema.size: UInt` compiles to mangled JVM names (`getSize-pVg5ArA`), which Java cannot call.
  - `Name(String)` has no `@JvmOverloads`.
  - Equality is inconsistent. Record equality ignores `doc` and aliases, like Apache. `FixedSchema` / `EnumSchema`
    (data classes) include them. `Field.equals` (data class) includes `doc` and aliases, but the record's field
    comparison ignores them. Pick one rule.
  - `toJsonElement(knownNamedTypes: MutableSet<String>)` / `fromJsonString(…, MutableMap)` expose mutable
    collections in public signatures.
  - `toApacheSchema()` parses with `NameValidator.NO_VALIDATION`, as kmp did.
- **Core quirk worth a backlog item:** core writes int defaults as `BigIntegerNode`. Apache's own
  `Field.defaultVal()` returns `null` for them, which affects any user who reads defaults of avro4k-generated
  schemas through Apache.
- **CI:**
  - `jsBrowserTest` needs a Chrome (ubuntu runners ship one).
  - Keep `org.gradle.jvmargs` ≥ 4g, or native linking thrashes.
  - Apple test targets still need a macOS runner (B0 note).
