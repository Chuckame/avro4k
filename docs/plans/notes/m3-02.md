# m3-02 — B2: avro4k's own binary codec ABI, Apache behind adapters

**Outcome:** done
**Commit:** `feat(core): own binary codec ABI in common, Apache behind adapters`

## What changed

### The ABI (`core/src/commonMain/.../internal/codec/`)

`@InternalAvro4kApi public abstract class`es, as decided in §4 (abstract classes: a vtable call is cheaper than an
interface call on Kotlin/Native). Every method is `abstract`, so each implementation is final.

| `AvroBinaryEncoder` | `AvroBinaryDecoder` |
|---|---|
| `writeNull()` | `readNull()` |
| `writeBoolean(Boolean)` | `readBoolean(): Boolean` |
| `writeInt(Int)` / `writeLong(Long)` | `readInt(): Int` / `readLong(): Long` |
| `writeFloat(Float)` / `writeDouble(Double)` | `readFloat(): Float` / `readDouble(): Double` |
| `writeString(String)` | `readString(): String`, `skipString()` |
| `writeString(utf8: ByteArray)` | `readStringBytes(): ByteArray` |
| `writeBytes(ByteArray)` | `readBytes(): ByteArray`, `skipBytes()` |
| `writeFixed(ByteArray)` | `readFixed(size: Int): ByteArray`, `skipFixed(size: Int)` |
| `writeEnum(Int)` / `writeIndex(Int)` | `readEnum(): Int` / `readIndex(): Int` |
| `writeArrayStart(count: Long)`, `startItem()`, `writeArrayEnd()` | `readArrayStart(): Long`, `arrayNext(): Long`, `skipArray(): Long` |
| `writeMapStart(count: Long)`, `writeMapEnd()` | `readMapStart(): Long`, `mapNext(): Long`, `skipMap(): Long` |

Counts are `Long`, like Apache's `setItemCount(long)` / `readArrayStart(): long`. No `flush()`: avro4k never flushed
the encoder it was given (the caller owns the sink), so the ABI has nothing to forward it to. Every returned
`ByteArray` is exclusively owned by the caller (KDoc contract), which is what `c5-readbytes` established by hand.

Also in common: `Varint.kt` — the zig-zag writers `encodeZigZagInt`/`encodeZigZagLong` (an unrolled port of Apache's
`BinaryData.encodeInt`/`encodeLong`, returning the byte count), the `MAX_VARINT_*_BYTES` constants now shared with the
decoder, and `checkBinaryLength` (negative, or above `MAX_BINARY_LENGTH = Int.MAX_VALUE - 8` →
`SerializationException`).

### Moved to common (`git mv`)

- `KotlinxIoEncoder` → `internal/codec/`, now an `AvroBinaryEncoder`. `writeInt`/`writeLong` keep the
  `writeToInternalBuffer` + `UnsafeBufferOperations.writeToTail(buffer, 5|10)` fast path but call the common
  writer instead of `BinaryData`. The collection and `writeBytes` semantics of Apache's `BinaryEncoder` it used to
  inherit are written out: a count is written only when > 0, the end is a single `0`, an empty `BYTES` is a single `0`.
  `bytesBuffered()`/`flush()` are gone (unused).
- `KotlinxIoDecoder` → `internal/codec/`, now an `AvroBinaryDecoder`. `readBytes`, `readStringBytes` and
  `readFixed` are `source.readByteArray(n)`: an exact copy, `require`d before allocation, safe across segments. This
  deletes the segment-wrapping fast path, the dead `old != null` branch and the private `readFully(ByteBuffer)` loop.
  Every length (`readString`, `readStringBytes`, `readBytes`, `skipString`, `skipBytes`) goes through
  `checkBinaryLength`; `readString()` and the skips were not checked at all before.
- `NumberUtils.kt` → common with the `Int`/`Long`/`Double` helpers; the six `BigDecimal` overloads stay in
  `jvmMain/.../internal/NumberUtils.jvm.kt`. `invalidTypeError` became `internal` so both files share it.

### Adapters (`core/src/jvmMain/.../internal/codec/ApacheCodecAdapters.kt`)

- `ApacheEncoderAdapter` / `ApacheDecoderAdapter`: the ABI over an Apache `Encoder`/`Decoder`. One ABI call is one
  Apache call, except `writeArrayStart(n)`/`writeMapStart(n)` → `writeArrayStart()`/`writeMapStart()` +
  `setItemCount(n)`; `writeString(utf8)` → `writeString(Utf8(utf8))`; `readStringBytes()` → `readString(null)`'s bytes
  (copied only if the `Utf8` array is longer than `byteLength`); `readBytes()` → `readBytes(null)` copied out of
  `position()..limit()` (the `c5-readbytes` helper, moved here); `readFixed(n)` → `readFixed(ByteArray(n))`.
- The reverse direction, for `validateSerialization` on avro4k's own codecs: `ApacheEncoderOverAbi` /
  `ApacheDecoderOverAbi`, private, only ever fed by a `ValidatingEncoder`/`ValidatingDecoder`, exposed through
  `AvroBinaryEncoder.validating(schema)` / `AvroBinaryDecoder.validating(schema)` =
  `Adapter(Validating(OverAbi(this)))`. `ApacheEncoderOverAbi` holds the pending `writeArrayStart()`/`writeMapStart()`
  until `setItemCount` arrives (an end without a count means 0).

### Entry points and internals

- `AvroInternalExtensions.kt`: `encodeWithApacheEncoder`/`decodeWithApacheDecoder` keep their Apache signatures
  (Confluent and `AvroObjectContainer` untouched); they wrap the given codec in Apache's validating codec when asked,
  exactly as before, then in the adapter. New internal `encodeWithValidation`/`decodeWithValidation` for avro4k's own
  codecs.
- `AvroKotlinxIoExtensions`: `KotlinxIoEncoder`/`KotlinxIoDecoder` directly, no Apache in the path unless validating.
- `AvroJVMExtensions.decodeFromByteBuffer` (public `inline`) now calls `@InternalAvro4kApi decodeFromByteBufferInternal`,
  which wraps a heap buffer's array into a kotlinx-io `Buffer` **without copying** (`UnsafeBufferOperations.moveToTail`,
  whose segments are never recycled nor written), copies a direct or read-only buffer, decodes, then advances the
  position by exactly the consumed bytes. No more `DecoderFactory`/`ByteBufferInputStream`.
- `AvroOkioExtensions`: encoding goes through `sink.outputStream().asSink().buffered()` and flushes it, as the
  `DirectBinaryEncoder` did. Decoding reads ahead, which would swallow the bytes of the next value (the old
  `DirectBinaryDecoder` read byte by byte), so it decodes from a counting `RawSource` over `source.peek()`, then
  `skip`s the original source by `bytesRead - bufferedButUnread`.
- Direct encoders/decoders and `AbstractAvroEncoder` take an `AvroBinaryEncoder`/`AvroBinaryDecoder`.
  `encodeStringUnchecked(Utf8)` became `encodeStringUnchecked(utf8: ByteArray)` (the generic encoder wraps it in `Utf8`,
  as before); `readString(null).bytes` became `readStringBytes()` in `decodeBytes`/`decodeFixed`, and
  `readString(null).single()` became `readStringBytes().decodeToString().single()` in `decodeChar` — equivalent, since
  `Utf8`'s `CharSequence` view (`length()`, `charAt()`) is its decoded `toString()`.

### What was removed from the codec path

`org.apache.avro.util.Utf8`, `java.nio.ByteBuffer` and `SystemLimitException` from the moved codecs (the acceptance
grep on `core/src/commonMain` is empty); `BinaryData`; `DecoderFactory`/`EncoderFactory` from the three public
entry-point files. **The `org.apache.avro.limits.*` system properties no longer apply to avro4k's own codecs** (they
still apply to an Apache decoder handed in to `decodeWithApacheDecoder`) — for B8's migration guide. Error types
changed on malformed input: a negative/oversized length is now a `SerializationException` (was `AvroRuntimeException`
/ `SystemLimitException` for bytes and `readString(Utf8)`, `IllegalArgumentException` for `readString()`/skips).

## How the Apache call sequence was kept identical, and how it was checked

By construction (one call per call, same overloads: `writeBytes(byte[])`, `writeFixed(byte[])`, `writeString(Utf8)`,
`readString(null)`, `readBytes(null)`, `readFixed(byte[])`), and by a golden test recorded **before** the change:

`core/src/jvmTest/.../internal/codec/ApacheCodecCallSequenceTest.kt` hands `encodeWithApacheEncoder` /
`decodeWithApacheDecoder` a recording Apache `Encoder`/`Decoder` (delegating to Apache's binary codec) and pins the
full call list for: a record with every type (null/non-null unions, boolean, int, long, float, double, string,
bytes, empty bytes, fixed, enum, array, empty array, map, nullable nested record, char); the same bytes decoded into a
one-field class (every skip path); and bytes/char/fixed values against a STRING writer schema (the `Utf8` paths).
Each case runs with `validateSerialization` off and on (with it on, the recorder sits behind Apache's validating
codec, so it sees what `ValidatingEncoder`/`ValidatingDecoder` forward). The golden lists were captured by running
the test on `86e4215` (10/10 green there), then pasted; the same 10 tests are green after the change. The two flags
record identical sequences.

## What was measured

Nothing: no benchmark was run (orchestrator's machine). Expected, for the A/B:

- **Decoding BYTES on the kotlinx-io path:** one exact `ByteArray` where there were `ByteBuffer.wrap` +
  `asReadOnlyBuffer` + a copy into a fresh array (small values), or a `ByteBuffer.allocate` + a second copy (values
  ≥ a segment). Fewer B/op on any record with a bytes field.
- **`decodeFromByteBuffer` on a heap buffer:** no copy of the input and no `DirectBinaryDecoder` /
  `ByteBufferInputStream` / per-read small allocations; it now takes the same (buffered, segment-scanning) varint path
  as `decodeFromByteArray`.
- **Encoding collections:** one virtual call to start an array/map instead of two (`writeArrayStart()` was a no-op).
- **Everything else:** neutral — the same kotlinx-io calls, the varint writer is Apache's unrolled code, and the call
  sites go from one abstract class (`org.apache.avro.io.Encoder`/`Decoder`) to another.

## What was rejected, and why

- **Keeping Apache's `writeArrayStart()` + `setItemCount()` pair in the ABI.** §4 fixes `writeArrayStart(count)`;
  the only cost is the pending state in `ApacheEncoderOverAbi`, which exists only on the validating path.
- **A new `@PublishedApi internal` helper for the inline `decodeFromByteBuffer`.** It would appear in `core.api`;
  an `@InternalAvro4kApi public` function is hidden by BCV's `nonPublicMarkers`, as the ABI is.
- **`inputStream().asSource().buffered()` for okio decoding.** It reads ahead, so a second `decodeFromSource` on the
  same okio source would have lost bytes. Nothing tested it; `AvroOkioExtensionsTest` now does.
- **Wrapping a read-only heap `ByteBuffer`'s array.** `hasArray()` is false for it, so it is copied; exposing its array
  would take reflection.
- **Starting the common validating codec.** M3-18, per Q2.

## Follow-ups

- **M3-07 / M3-14:** `ApacheCodecAdapters.kt` moves to `apache-interop` next to `encodeWithApacheEncoder` /
  `decodeWithApacheDecoder` (same names and package). `decodeFromByteBufferInternal` and the okio peek source are
  plain JVM code and stay in core's `jvmMain`.
- **M3-18:** a common validating `AvroBinaryEncoder`/`AvroBinaryDecoder` replaces `validating(schema)` (the only use
  of the `OverAbi` bridges, which can then be deleted), differentially tested against Apache's validating codecs —
  `ApacheCodecCallSequenceTest`'s recording codecs are a ready harness for that.
- **M3-12:** `ApacheCodecCallSequenceTest` (like `ReadBytesBufferBoundsTest`) builds Apache `Schema`s by hand and reads
  `AvroDecoder.decodeFixed()`; it tests the Apache-typed internal API, so it follows that API to `apache-interop`
  (or through M3-01's bridge) rather than to `AvroSchema`.
- **M5/C5:** the non-allocating `writeString(String)` (a `TODO` marks it); `readString()` already decodes straight
  from the source.
- `KotlinxIoDecoder.readVarLong` uses `request(1)` where `readVarInt` uses `require(1)`: at end of input it fails with
  `IllegalStateException("Unreachable")` instead of `EOFException`. Pre-existing, left alone.
