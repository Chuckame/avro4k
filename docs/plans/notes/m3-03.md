# M3-03 — Downstream bridges

**Outcome:** done
**Commit:** `refactor(confluent, benchmark): route schema-typed core calls through local bridges`

`confluent-kafka-serializer` main code, `benchmark` main code and their two build files only. No file under `core/`,
`apache-interop/` or `kotlin-generator/`, no `.api` change, no `@Benchmark` method body touched. Perf-neutral: every
helper is an identity today (no benchmark was run, per the brief; the benchmark module is only compiled).

## What changed

- **New `confluent-kafka-serializer/src/main/.../kafka/confluent/CoreBridge.kt`** and
  **new `benchmark/src/main/kotlin/.../benchmark/internal/CoreBridge.kt`**: the only files of their module that call core's
  schema-typed API (outside `@Benchmark` methods for the benchmark). All helpers are `internal`.
- **Both build files** get `implementation(project(":apache-interop"))`. Nothing calls it yet; it is there so that M3-12
  only edits the bridge bodies. No circular-dependency problem here (unlike M3-01): neither module is a dependency of
  `apache-interop`.
- **Confluent** (`Serializers.kt`, `AbstractAvro4kKafkaSerde.kt`, `SpecificAvro4kKafkaSerde.kt`): every `avro.schema(…)`,
  `currentWriterSchema` read, `decodeFixed()`, `encodeWithApacheEncoder`/`decodeWithApacheDecoder` call,
  `MissingFieldsEncodingException(List<Field>, Schema)` construction and override of a schema-typed core hook now goes
  through the bridge. One micro-change: `GenericRecordKSerializer.deserializeAvro` reads the writer schema once into a
  local instead of twice (same value: both reads were on the outer decoder), so M3-12 converts once per record, not twice.
- **Benchmark**: every schema field a measured avro4k method hands to core is now typed `CoreSchema` (the alias), and
  every `@Setup`/`setup()`/`prepareBinaryData()`/equivalence-gate/`.avsc`-generator call goes through the bridge.

### Confluent bridge surface

| Helper | Today | M3-12 body |
|---|---|---|
| `typealias CoreSchema` | `= Schema` | `= AvroSchema` (import avro4k's, see the name-clash trap below) |
| `CoreSchema.asApacheSchema(): Schema` | `this` | `toApacheSchema()` (identity-cached) |
| `Avro.apacheSchema(descriptor): Schema` | `schema(descriptor)` | `schema(descriptor).toApacheSchema()` |
| `AvroDecoder.apacheWriterSchema: Schema` | `currentWriterSchema` | `currentWriterSchema.toApacheSchema()` |
| `AvroEncoder.isWriterSchemaUnion: Boolean` | `currentWriterSchema.isUnion` | `currentWriterSchema is AvroSchema.UnionSchema` (no conversion) |
| `AvroDecoder.decodeGenericFixed(): GenericFixed` | `decodeFixed()` | `GenericData.Fixed(currentWriterSchema.toApacheSchema(), decodeFixed())`, once `decodeFixed()` returns bytes |
| `missingFieldEncodingException(field: Schema.Field, writerSchema: Schema)` | `MissingFieldsEncodingException(listOf(field), writerSchema)` | the exception's new schema-typed constructor, or its `(message)` constructor with today's exact message |
| `Schema.isNamedSchema()` | **local copy** of core's `internal.isNamedSchema` (pure Apache) | unchanged |
| `Avro.encodeWithApache(writerSchema, serializer, value, encoder)` | `encodeWithApacheEncoder(…)` | unchanged if the entry point keeps its Apache signature; only the import if it moves to `apache-interop` (M3-14); `writerSchema.toAvro4k()` if core retypes it |
| `Avro.decodeWithApache(writerSchema, deserializer, decoder)` | `decodeWithApacheDecoder(…)` | as above |

Where the hooks use them: `ReflectKSerializer`'s six `AnySerializer` overrides and `GenericKSerializer`'s three now take
`writerSchema: CoreSchema`; `ReflectKSerializer` converts once at the top of each (`writerSchema.asApacheSchema()`) and keeps
its Apache-based body (`getProp(java-class…)`, `fullName`, `aliases`). The three `getSchema(context): CoreSchema` overrides
throw, so they only need the alias.

**Not bridged, on purpose:**
- `trySelectNamedSchema(name, aliases)` and `namedSchemaNotFoundInUnionError(name, aliases)`: the `String` overloads, not
  schema-typed. (The latter's `vararg fallbackTypes: Schema.Type` is not passed, so the call compiles whatever M3-12 makes
  of that parameter.)
- `com.github.avrokotlin.avro4k.internal.aliases` (a `SerialDescriptor` extension) and `Cache`/`WeakKeyCache` (generic).
- This module's own public, Apache-typed API (`AbstractAvro4kKafkaSerializer.getSchema(value): Schema`,
  `AbstractAvro4kKafkaDeserializer.schema: Schema?`, `getDatumReader(writerSchema: Schema, …)`): these are Confluent's
  world, not core calls, and stay Apache-typed (locked decision 1: Apache interop is explicit and JVM-only).

### Benchmark bridge surface

| Helper | Today | M3-12 body |
|---|---|---|
| `typealias CoreSchema` | `= Schema` | `= AvroSchema` |
| `CoreSchema.asApacheSchema(): Schema` | `this` | `toApacheSchema()` |
| `Schema.toCoreSchema(): CoreSchema` | `this` | `toAvro4k()` |
| `Avro.coreSchema<T>()`, `Avro.coreSchema(descriptor)` | `schema<T>()` / `schema(descriptor)` | unchanged |
| `Avro.apacheSchema<T>()` | `coreSchema<T>().asApacheSchema()` | unchanged (delegates) |
| `Avro.encodeWith(writerSchema: CoreSchema, [serializer,] value)` | `encodeToByteArray(…)` | unchanged |
| `Avro.decodeWith(writerSchema: CoreSchema, [deserializer,] bytes)` | `decodeFromByteArray(…)` | unchanged |

So at M3-12 exactly three lines of the benchmark bridge change. The design choice: the `schema` fields are typed
`CoreSchema` rather than kept Apache-typed, because the avro4k `@Benchmark` methods pass them to core and may not be
edited. The competitors (Apache generic fast reader, Jackson) and the equivalence gate need Apache, so they call
`schema.asApacheSchema()` in `setup()` — once per trial, never in a measured method.

Where it is used:
- `Serialization{,Lists,Simple}Benchmark.schema: CoreSchema = Avro.coreSchema<…>()`; every library's
  `prepareBinaryData()` uses `Avro.encodeWith(schema, …)`; the three `ApacheAvroGenericFastReader*` and three
  `JacksonAvro*` `setup()`s use `schema.asApacheSchema()`.
- Micro: `Polymorphic`, `StringField`, `Collection`, `NestedRecord`, `FieldOrder` fields typed `CoreSchema`, their
  `@Setup` through `coreSchema`/`encodeWith`; `SchemaInference`'s cache-warming `@Setup` call through `coreSchema`.
  `FieldOrder` builds its mismatching writer schemas from `Avro.apacheSchema<T>()` with the Apache API and hands them over
  with `.toCoreSchema()`; the `matching` control uses `Avro.coreSchema<T>()`, i.e. core's cached instance, exactly as before.
- `WorkloadEquivalence`: per workload, `coreSchema = Avro.coreSchema<T>()` for every avro4k encode/decode and
  `canonicalSchema = coreSchema.asApacheSchema()` for the gate, the Apache generic library and Jackson.
- `CanonicalSchemas` (the `.avsc` generator): `Avro.apacheSchema<T>()`.

## Traps for M3-12 and B7

- **`GenericData.Fixed(…)`** (`decodeGenericFixed`). Today core's `decodeFixed()` returns an Apache `GenericFixed` built
  with the writer schema. Once it returns bytes, the bridge must rebuild it with the Apache writer schema; with M3-05's
  two-way seeding `toApacheSchema()` returns the Confluent registry's original Apache node, so `GenericFixed.getSchema()`
  identity is preserved. Without seeding it is a structurally equal copy — `SpecificData`/`GenericData.equals` still work,
  identity checks would not.
- **Per-value conversions.** `apacheWriterSchema` (enum symbols, generic records), `asApacheSchema()` in the six
  `ReflectKSerializer` hooks and `decodeGenericFixed` run per decoded value. At M3-12 they become identity-cached
  `toApacheSchema()` lookups (a `WeakIdentityKeyCache` hit each) — explicitly accepted until B7 (§7). B7 should resolve
  these hooks against `AvroSchema` directly (it has `props`, names and aliases) instead of converting.
- **`isWriterSchemaUnion`** is deliberately not `apacheWriterSchema.isUnion`: it is on the encode path of every generic
  enum/fixed/record value and needs no conversion at M3-12.
- **`ThreadLocal<Schema>` in `SpecificAvro4kKafkaDeserializer`** carries the Confluent-provided Apache writer schema from
  `getDatumReader` to `deserialize` for root STRING/BYTES. It never crosses into core, so M3-12 leaves it alone (the root
  decode goes through `decodeWithApache` with that Apache schema). It is shared per-thread state outside the
  decoder — a B7 candidate under the "per-operation state on the decoder, anything else designed away" rule. It is also
  left set if `super.deserialize` throws between the two calls.
- **Caches keyed by Apache `Schema`.** `GenericRecordKSerializer.cache` is a core `WeakKeyCache<Schema, SerialDescriptor>`:
  keyed by **equality** (Apache `Schema.hashCode` is cached, but `equals` is a structural walk on a hash collision or a
  fresh instance). The keys are `IndexedRecord.schema` / the writer schema, i.e. registry-provided Apache instances, so it
  is unaffected by M3-12; B7 should move it to identity keys. Confluent's own registry client caches (keyed by
  `io.confluent…AvroSchema(schema)`, built per `serialize` call today) are untouched by this unit.
- **Name clash.** `AbstractAvro4kKafkaSerde.kt` imports `io.confluent.kafka.schemaregistry.avro.AvroSchema`. M3-12 must
  not add avro4k's `AvroSchema` import there; the alias in `CoreBridge.kt` is the only place that needs it.
- **`MissingFieldsEncodingException` message.** No Confluent test asserts on it today (grep of `src/test`), but it is
  user-visible; keep today's exact message (via the `(message)` constructor if needed).
- **Round-trip fidelity in the benchmark gate.** After M3-12, `canonicalSchema` and the `.avsc` files come from
  `toApacheSchema()` of core's schema. Any conversion artefact (ledger B1 row: integer-literal defaults for float fields,
  big-integer int defaults) would surface as an equivalence-gate failure in `@Setup` or an `.avsc` diff on
  `regenerateAvroSchemas`. The checked-in `.avsc` files carry field defaults (15, 3 and 3 of them), so M3-12 should run
  `regenerateAvroSchemas` once and expect no diff; a failure there is the converter, not the benchmark.
- **FieldOrder's hand-built writer schemas** become `toAvro4k()` conversions of a fresh Apache schema, once per trial in
  `@Setup`; the instance is then reused by every measured call, so core's identity caches hit as before.

## What was rejected, and why

- **Accessor-level bridging in `ReflectKSerializer`** (`CoreSchema.prop(key)`, `.fullName`, `.aliases` helpers, so M3-12
  could read `AvroSchema` without converting): more surface for a module that has to stay Apache-based anyway
  (`GenericData.Record`, `GenericData.EnumSymbol`, the registry). One `asApacheSchema()` per hook, identity-cached at
  M3-12, is what §7 already accepts until B7.
- **Apache-typed benchmark fields plus a separate core-typed copy**: the avro4k `@Benchmark` methods reference the
  existing field names, so they would have had to change.
- **Changing the `SchemaInference` `@Benchmark` return types to `CoreSchema`**: it would spare M3-12 two edits, but the
  brief forbids touching `@Benchmark` methods; they are listed above instead.

- None blocking. B7: drop the per-value conversions and the `ThreadLocal`, identity-key the generic-descriptor cache.
