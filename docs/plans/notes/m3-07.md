# M3-07 — `AvroSchema` helper layer

**Outcome:** done. No locked decision touched. Dead code until M3-09 (as planned): no main-code call site changed.
**Commit:** the one that adds this file (`git log -1 -- docs/plans/notes/m3-07.md`).

## What changed

- **New `core/src/commonMain/.../internal/schema/AvroSchemaHelpers.kt`**: 25 helpers (28 declarations with the
  overloads), every one `internal`. **No `@InternalAvro4kApi`:** no other module needs them before M3-12. Confluent
  uses only `isNamedSchema`, through its `CoreBridge` and core's existing public Apache-typed version. M3-12 decides
  whether that one becomes `@InternalAvro4kApi` on `AvroSchema`.
- **New tests:**
  - `commonTest/.../internal/schema/AvroSchemaHelpersTest.kt` (22) and `AvroSchemaSkipTest.kt` (11). They run on jvm,
    js and native.
  - `jvmTest/.../internal/schema/AvroSchemaHelpersDifferentialTest.kt` (10).
- **`.api`:** unchanged (everything is `internal`).
- **Package:** `com.github.avrokotlin.avro4k.internal.schema`, the package of the jvmMain visitors that M3-09 rewrites.
  So the visitors pick the helpers up without an import. There is no name clash: every helper takes an `AvroSchema`
  receiver, while the jvmMain ones take an Apache `Schema` receiver, so they are overloads.

### Hot-path rules, checked

- **No structural equality.** The acceptance grep over the new file finds `==` only on `String`s (full names, logical
  type names) and on `Int` indexes, and `===` only on the `Type` enum. The only `indexOfFirst` calls take a predicate
  lambda. They are in `moveTo{Head,Tail}OfUnion`, which runs during schema generation (a cold path).
- **No allocation on the lookup paths.**
  - `getIndexTyped` and `getIndexLogicallyTyped` are indexed loops over `types` that compare the stored `type` and the
    cached `logicalTypeName`. They return `Int` (**-1** when absent), not `Int?`, so they never box.
  - The Apache helper took a `vararg`. It is replaced by 1-type and 2-type overloads, the only arities the call sites
    use, so no array is allocated per call.
  - `isFullNameMatch` allocates nothing when the full name matches.
  - `isFullNameOrAliasMatch` is `inline`, so a lambda or a bound reference passed as `aliases` is not allocated.
  - `skip` uses indexed loops, with no iterator.
- **The M3-04 caches are used, never re-derived:**
  - the stored `type` everywhere;
  - `logicalTypeName`;
  - `EnumSchema.getSymbolIndexOrNull` (`hasEnumSymbol`, `getEnumOrdinal`);
  - `UnionSchema.getIndexOrNull` (`getIndexNamedOrAliased`);
  - `FixedSchema.size: Int`.
- **Allocation that remains, on error and miss paths only:** `aliases` / `nonFailingAliases` (they map `Name` to
  `String`), `fullNameForMessages` for a union, `toSchemaJsonString`, and `asSchemaList` for a non-union (`listOf`,
  as before, on cold paths).
- **Cached record lookups:** no helper calls `RecordSchema.getField*` (M3-04's rule about unlocked records). `fields`
  reads the list only.

## Semantic subtleties found

1. **A union's full name.** Apache's `UnionSchema.getName()`, and hence `getFullName()`, is
   `"union[" + <branches' simple names joined by ", "> + "]"`, for example `union[null, R, array]`. The model's
   `UnionSchema.fullName` is `"union"`.
   - This matters in error messages, because every `unsupportedWriterTypeError` interpolates
     `currentWriterSchema.fullName` while the writer schema is still the unresolved union. `fullNameForMessages`
     reproduces Apache's string.
   - It would also matter in `isFullNameMatch` on a union. No call site does that: all of them resolve the union
     first, or are inside a `RECORD`/`ENUM`/`FIXED` branch. The differential test pins the difference.
   - No existing test asserts a `union[` message.
2. **The schema in messages.** Apache interpolates `Schema.toString()`, which is compact JSON. The model's
   `toString()` is a data-class dump. So M3-11 must interpolate `toSchemaJsonString()` (`toJsonElement().toString()`),
   not `$currentWriterSchema`. Otherwise `GenericDataMapEncodingTest.kt:198` breaks (`"Cannot encode null value for
   non-null schema: \"string\""`); it is the only test in core and Confluent that pins a message embedding a schema.
   The JSON is identical to Apache's for schemas without a named type (the differential test checks every such
   message in full). For named types the key order is the model serializer's own, so only the prefix is checked.
3. **Logical types: raw prop vs Apache's validated `LogicalType`.**
   - Apache's `getLogicalType()` is `null` when the `logicalType` prop names a type Apache does not know, for
     example avro4k's own `char` or `big-decimal`-like names on a schema that went through `Schema.Parser`. avro4k's
     generator sets the field directly with `LogicalType(name).addToSchema`, so its own schemas are unaffected.
   - It is also `null` when validation fails, for example `date` on a string, or `decimal` without `precision`.
   - `logicalTypeName` is the raw prop in both cases. So `getIndexLogicallyTyped` can select a branch that Apache
     would skip, and M3-11's `logicalTypeName ==` checks in the serializers accept what Apache ignored.
   - Pinned by a differential test (`date` on a string). It is the more useful behaviour for `char`. For an invalid
     `decimal` it moves the failure from "branch not found" to the converter. M3-11 should decide whether that is
     acceptable, and record the decision for B8.
4. **`getIndexTyped` of a named type.** Apache implemented it as `getIndexNamed(type.getName())`: a *name* lookup,
   which for `RECORD` matches a record literally named `record` (a legal name, since Apache only forbids primitive
   names). The port is a type lookup (the first branch of that type). No call site asks for a named type, and it is
   pinned by a differential test. For unnamed types the two agree exactly, because a union has at most one branch per
   unnamed type in both models.
5. **`Int` with -1, not `Int?`** from `getIndexTyped` / `getIndexLogicallyTyped` (no boxing). M3-11 must write
   `if (index < 0) return false`. Beware: `?: return false` on an `Int` only produces a warning, and the build does not
   treat warnings as errors. `getIndexNamedOrAliased` keeps `Int?`: it returns the union map's own box, so nothing is
   allocated, as in M3-04.
6. **Exception class.** Apache throws `AvroRuntimeException` (a direct `RuntimeException` subclass). Common code
   cannot, so the accessors throw exactly `RuntimeException`, with Apache's message. It is neither
   `IllegalStateException` nor `IllegalArgumentException`, so no `catch (SerializationException)` starts catching it.
   The only catch site in the runtime, `getEnumOrdinalChecked`, catches `Exception`. No test in core, apache-interop
   or Confluent asserts `AvroRuntimeException` on these paths (grepped). An unknown enum symbol was a
   `TracingAvroTypeException` wrapping the message. It is now a plain `RuntimeException` with the same message, which
   `getEnumOrdinalChecked` wraps as the cause anyway.
7. **Aliases are full names**, as Apache's `getAliases()`. The model rejects a union where a name is both a branch's
   full name and another branch's alias, which Apache accepts. So `getIndexNamedOrAliased`'s single lookup equals
   Apache's "names first, then aliases". Such Apache schemas already fail at `toAvro4k()`.
8. **`skip`** makes exactly the same `AvroBinaryDecoder` calls as the Apache-typed skip, in the same order. The only
   differences are that it iterates the record fields by index instead of with a `forEach` iterator, and that `UNION`
   after resolution is unreachable, since the model's union branches are `ResolvedSchema`s.
9. **`moveTo*OfUnion`** keeps two quirks: it builds a new union even when the branch is already in place, and a
   negative index throws `IndexOutOfBoundsException`. Both are pinned by tests.

## What was rejected, and why

- **`Int?` returns for the type lookups**, to keep the Apache signature. That signature boxes. On the JVM and native
  a small index hits the box cache, but the brief rules out boxing, and a sentinel costs nothing.
- **One `vararg` `getIndexLogicallyTyped`**: it allocates an array per call.
- **`@InternalAvro4kApi public` for `isNamedSchema`** now. Confluent does not need the `AvroSchema` version until
  M3-12, which owns that API change.
- **A dedicated `AvroRuntimeException`-like class in common.** It would be a new type that nobody catches.
  `RuntimeException` is AvroRuntimeException's own superclass, so every existing `catch` behaves the same.
- **Comparing the differential against core's Apache-typed helpers.** The test would break at M3-11. It uses a frozen
  copy instead.
- **Normalizing `logicalTypeName` to Apache's validated view.** That would re-open M3-04's decision (raw prop, never
  throws). It is flagged for M3-11 instead (subtlety 3).
