# M3-09 — Visitors → `AvroSchema`, Jackson dropped

**Outcome:** done. No locked decision touched. Not api: `core.api` and `apache-interop.api` unchanged.
The schema generation builds avro4k's `AvroSchema`. `Avro.schema()` still returns Apache's `Schema`: it is the cached,
paired Apache form of the generated `AvroSchema`. No Jackson type is left in core's schema generation:
`grep -rn "com.fasterxml" core/src/jvmMain` only finds `internal/AvroSchemaApacheConversion.kt` (the hosted converter,
moved out by M3-14).
**Commit:** the one that adds this file (`git log -1 -- docs/plans/notes/m3-09.md`).

## What changed

Paths are relative to `core/src/jvmMain/kotlin/com/github/avrokotlin/avro4k/`.

- **`internal/schema/*` (the 8 visitor files)** build the common model: `RecordSchema` (with a `LockableList` of fields),
  `EnumSchema`, `ArraySchema`, `MapSchema`, `UnionSchema` and the primitive schemas. They are fed by the M3-07 helpers
  (`asSchemaList`, `moveTo{Head,Tail}OfUnion`, `isNonNullScalarType`, `isNamedSchema`, `toSchemaJsonString`,
  `fullNameForMessages`), all in the same package.
  - `ClassVisitor` registers the record before visiting its fields (recursive records, as before). It **locks** the
    fields in `endClassVisit`, before the record is handed on, as M3-04 requires. The union reordering for defaults is
    unchanged, but it runs on `logicalTypeName` and `type ===` rather than on Apache's `logicalType?.name`. The default is
    written as the json that `toFieldDefault` returns. The old `JsonElement.toAvroObject()` (json → `BigInteger` /
    `BigDecimal` / `NULL_VALUE` for Apache's `Field` constructor) is deleted.
  - `ValueVisitor`: `PrimitiveKind.CHAR` is `IntSchema(props = {"logicalType": "char"})`. `@AvroGenerated` is parsed
    with the common `AvroSchema.fromJsonString` instead of Apache's parser. Every primitive node is a fresh instance,
    never a shared constant, because pairing (M3-05) pairs a node only once.
  - `InlineClassVisitor`: `Schema.copy(additionalProps = …)` becomes a private `withAdditionalProps`, a data-class
    `copy(props = …)` of the unnamed schema.
  - `ListVisitor`, `MapVisitor` and `PolymorphicVisitor` are straight swaps. `MapVisitor`'s Apache-typed
    `isNonNullScalarType` is deleted, since the M3-07 port replaces it.
  - `VisitorContext.resolvedSchemas` is now `MutableMap<String, NamedSchema>`, and `VisitorContext.shareNamedSchema`
    is new (see the next section). The file also holds the Apache-compatible name and prop helpers:
    `toSchemaProps`, `addProp`, `namedSchemaName`, `toSchemaAliases`, `validateAvroName`, and the three reserved-prop
    sets.
- **`internal/helpers.kt`**:
  - `AvroProp.jsonNode` (Jackson `ObjectMapper` / `TextNode`) becomes `AvroProp.jsonElement`
    (`Json.parseToJsonElement`, else `JsonPrimitive`). It follows the same "looks like json" rule as `@AvroDefault`, but
    it does not normalize numbers. The three Jackson imports are gone.
  - The Apache-typed `Schema.nullable` is deleted, since its only user was `ValueVisitor`.
  - `Schema.asSchemaList`, `Schema.copy` and `Schema.Field.copy` stay: `RecordResolver`, the Apache variants in
    `AvroDefaults.kt` and the serializers' `getSchema` bodies still use them.
- **`Avro.kt`**:
  - `schemaCache` is now an `IdentityFirstCache<SerialDescriptor, GeneratedSchema>`. `GeneratedSchema` is a small
    immutable holder of the `AvroSchema` and its Apache form, which it computes eagerly in its constructor.
  - `schema(descriptor)` returns `generatedSchema(descriptor).apacheSchema`. The new internal `avroSchema(descriptor)`
    returns `.avroSchema`. Both are one `IdentityFirstCache` lookup plus one field read, as the brief requires.
  - The Apache form comes from `avro4kToApacheKeepingUnknownLogicalTypes` (below), which is identity-cached and paired.
    So its identity is stable per cache entry, and every node of both trees is paired both ways.
- **`serializer/AvroSerializer.kt`**: new internal `AvroSchemaSupplier.getAvroSchema(context)` =
  `apacheToAvro4kUncached(getSchema(context))`.
  - It is the **uncached** converter, because `getSchema` results are fresh per call.
  - The public `getSchema(context): Schema` is unchanged.
  - Every built-in `AvroSerializer` goes through this supplier: `KotlinStdLibrarySerializers`, `JavaTimeSerializers`,
    `JavaStdLibSerializers`, `AvroDuration`, the `ByteArray`/`String`/`Duration` ones in `SerializerLocatorMiddleware`,
    and Confluent's. So each pays **one uncached Apache → avro4k conversion per use, per schema generation**. That is a
    cold path: `Avro.schema()` caches the result per descriptor. M3-12 deletes the supplier when `getSchema` flips.
- **`internal/AvroDefaults.kt`** is ported (see "Defaults" below).
- **`internal/AvroSchemaApacheConversion.kt`**:
  - The public `avro4kToApache` is unchanged in signature and behaviour. It now delegates to a private overload.
  - A new internal `avro4kToApacheKeepingUnknownLogicalTypes` does the same cached, paired conversion. Before seeding,
    while the parsed nodes are still private to the call, it gives back the logical types that Apache's parser drops
    (below).

## Semantics: what was preserved, and how

The whole `schema/` suite in `core/src/jvmTest` passes **unchanged**, including the `toString(true)` golden comparisons,
with no prop-ordering fix needed. Props keep the annotation order, because `toSchemaProps` fills a `LinkedHashMap` and
the json writes props in map order. The rest of `:core:jvmTest`, apache-interop and Confluent pass too, with only the
test changes listed below.

Points that needed care:

1. **Unknown logical types.** Apache's parser keeps a logical type only if it knows it. So on the json route,
   `getLogicalType()` would have become `null` for avro4k's own `char`, and for any custom logical type that a user's
   `AvroSerializer.getSchema()` sets. Core's runtime still reads `getLogicalType()` until M3-11, for example
   `toFieldDefault` for char defaults on the decode side, and `AnySerializer` for the configured logical types.
   - `avro4kToApacheKeepingUnknownLogicalTypes` re-applies `LogicalType(name).addToSchema(node)` to every parsed node
     whose `logicalType` prop names a type that is neither one of Apache's 13 built-in names nor a registered custom
     one. That is exactly what the former generation did.
   - A known logical type that Apache rejects as invalid stays dropped, as Apache's parser would drop it. The former
     generation could not produce one: `copy(logicalType = …)` validates it.
   - Apache's `Schema.equals` ignores `logicalType`, so equality-based tests are unaffected.
2. **Named types are one instance per generated schema** (new `VisitorContext.shareNamedSchema`, applied in
   `ValueVisitor.setSchema`).
   - The generation used to build an enum, or a serializer's fixed, anew at every use. The json route then gives one
     Apache node for all of them (the parser shares named types), and pairing can pair only one of the equal avro4k
     instances. `AvroSchemaApacheIdentityTest."schemas generated by avro4k are paired at every node, both ways"` caught
     it, on the `Suit` enum used twice in `Everything`.
   - So an equal duplicate is replaced by the first instance. This is the only structural `==` on schemas in this unit;
     it runs only when a full name is met again with another instance (see the equality grep below).
   - A union's named branches are shared the same way.
   - **Behaviour change:** two *different* named schemas with the same full name now fail generation with
     `AvroSchemaGenerationException`. An example is two `@AvroFixed` fields with the same name in the same namespace but
     different sizes (the fixed is named after the field).
     - Before, `Avro.schema()` held two distinct in-memory nodes. But its `toString()` wrote the second one as a name
       reference, so any registry or reader saw the first definition. The json route cannot represent that case at
       all: it would silently use the first size, or the first precision.
     - A record whose serial name was already resolved keeps the old rule: the first one wins, silently.
     - An enum or a fixed meeting a record of the same name is rejected.
3. **Apache's validations are kept**, with their messages. The model does not check these the way Apache did, so the
   visitors check them before building the model:
   - names: record and enum simple names, enum symbols, record and enum aliases, and field names, with
     `NameValidator.UTF_VALIDATOR`'s rule;
   - reserved props: `SCHEMA_RESERVED`, `ENUM_RESERVED` and `FIELD_RESERVED` (this includes `order` on a field, which
     the model would otherwise accept as a prop and write as the field's sort order);
   - props: the same prop twice with another value is rejected ("Can't overwrite property"), and with the same value it
     is kept once.

   **The exception class changes** from Apache's `SchemaParseException` / `AvroRuntimeException` to
   `AvroSchemaGenerationException` (a `SerializationException`). No test pinned the old classes (grepped). The one
   Apache exception kept on purpose is **`AvroTypeException` for an invalid field default**: its message is Apache's
   `Field` constructor message, and `schema/AvroDefaultSchemaTest` pins the class.
4. **Default values in the Apache form** are Apache-parsed json nodes: `IntNode` / `LongNode` / `DoubleNode`, instead of
   the `BigIntegerNode` / `DecimalNode` that core used to build. `Field.defaultVal()` now returns the value (for
   example `42`), where it used to return `null` for a big-integer node. The text of the json is identical, so
   `toString()` is unchanged.
5. **What the json cannot hold is gone from the Apache form**:
   - props on a union: a value class with `@AvroProp` over a nullable type. Apache kept them in memory, but it never
     wrote them;
   - two distinct instances of one named type (point 2);
   - `isError` (never set by the generation).

   Name validation of the Apache form: the json route parses with `NameValidator.NO_VALIDATION` (M3-05), which is why
   the visitors validate names themselves (point 3).
6. **`@AvroGenerated`** goes through `AvroSchema.fromJsonString`. Differences with Apache's parser: names are not
   validated, and a default is kept as written, not coerced to its type the way Apache's `defaultVal()` coerces it.
   With the coercion, `36` for a float would have become `36.0` after the round trip; without it, the Apache form keeps
   `36`, which is what Apache's parser gave before. The one test, `AvroGeneratedTest`, passes unchanged.
7. **Model-side checks that Apache made differently:**
   - a duplicate union branch, and a duplicate field name, are now the model's `IllegalArgumentException`, where Apache
     threw an `AvroRuntimeException`;
   - a nested union in a polymorphic type throws `AvroSchemaGenerationException("Nested union: …")`, Apache's message.
8. **Messages** embed `toSchemaJsonString()`, the same compact json as Apache's `toString()`.
   `toSchemaJsonStringOrName()` falls back to the name for a recursive record still being built: its fields cannot be
   read before they are locked. A recursive map key used to fail on that; it is pinned by a new test.

### Defaults (`internal/AvroDefaults.kt`)

- `toFieldDefault`, `isValidDefaultFor` and `resolveDefaultBranch` each exist twice until M3-11: once on `AvroSchema`,
  for the generation, and once on Apache's `Schema`, for `RecordResolver` and `JsonDefaultDecoder`. **The rules are
  written once:**
  - the parsing, number normalization, `"null"` and char logic are in a private `toFieldDefault(isNullable, isChar)`;
  - the leaf-type table, including the bytes/fixed **0-255 rule**, is in `isValidDefaultForLeaf(AvroSchema.Type, …)`.

  Each variant only walks its own model: arrays, maps, records and unions.
- The 0-255 rule stays **generation-only**. The common model's `isValidJsonForSchema` (commonMain) is untouched, so
  `toAvro4k()` still accepts every schema Apache Java accepts.
- The `AvroSchema` variant of the record rule accepts any json object for a record that is still being built, because
  the fields of a recursive record are not locked yet. This mirrors the model's own check. Apache's `getFields()`
  threw in that case; the final Apache parse still validates the default.
- The `@AvroDefault("null")` decision (2026-09-24) is **kept as is**. Porting it added no complexity: it is one branch
  on `isNullable`, the same in both models.
- `resolveDefaultBranch(AvroSchema)` has no caller yet. It is ported for M3-11.

## Structural-equality grep

`==`, `!=`, `indexOf`, `contains` and `in` over every changed main file. The only structural `==` on a schema is in
`VisitorContext.shareNamedSchema` (`isEqualTo`): cold, since it runs once per repeated full name per generation. It is
what tells an equal duplicate from a conflict. Everything else compares:
- `String`s: full names, `logicalTypeName`, prop names;
- `AvroSchema.Type` enums, by identity;
- `JsonElement` prop values (`addProp`'s "same value" check, as Apache compared `JsonNode`s);
- descriptor kinds.

The `moveTo*OfUnion` predicates compare types and logical type names only.

## Performance

Not benchmarked, as the brief planned.

- **Warm path unchanged by construction.** `Avro.schema(descriptor)` is still one `IdentityFirstCache` lookup, plus
  one field read on the holder (`GeneratedSchema.apacheSchema`). `RecordResolver` and `PolymorphicResolver` call it as
  before. `SchemaInferenceMicroBenchmark.warmCacheHit` should not move.
- **Cold path slower, not gated.** A schema generation now also does:
  - one `toJsonElement` render;
  - one `Json.encodeToString`;
  - one Apache `Schema.Parser` parse;
  - the pairing walk and the logical-type restore walk;
  - one uncached Apache → avro4k conversion per custom-serializer use;
  - inserts into the two **global** weak identity conversion caches, one entry per node, each an O(capacity)
    copy-on-write put.

  `SchemaInferenceMicroBenchmark.coldInference` builds a new `Avro` per operation. So it also keeps adding entries to
  those global caches until the garbage collector reclaims them (M3-05's deferred reclamation). Expect it to be
  noticeably slower, and noisier, than before.

## For the next units

- **M3-11 (runtime flip):**
  - Switch `RecordResolver` and `JsonDefaultDecoder` to the `AvroSchema` variants. The reader schema is
    `avro.avroSchema(descriptor)`, the same cache entry.
  - Then delete the Apache-typed `toFieldDefault(Schema)`, `isValidDefaultFor(Schema)`, `resolveDefaultBranch(Schema)`
    and `Schema.Type.toAvroSchemaType()` in `AvroDefaults.kt`, and `Schema.asSchemaList()` in `helpers.kt`, once
    `RecordResolver` stops using it.
  - Decide whether the facade's `toApacheSchema` should also keep unknown logical types
    (`avro4kToApacheKeepingUnknownLogicalTypes`). That ties in with M3-07's subtlety 3.
- **M3-12 (public flip):**
  - `AvroSchemaSupplier.getSchema` returns `AvroSchema`, so delete `getAvroSchema` and its uncached conversion.
  - `schema()` returns `GeneratedSchema.avroSchema`. The holder can then drop `apacheSchema`, unless the facade still
    needs it.
  - The serializers' `copy(logicalType = …)` bodies become model constructors. If that pattern repeats there, add
    M3-07's `withLogicalType(name)`: the visitors needed it only once (`char`), so it was not added here.
- **M3-13 / M3-14:**
  - `ClassVisitor` still throws Apache's `AvroTypeException` for an invalid default, because
    `schema/AvroDefaultSchemaTest` pins that class. When Apache leaves core, that test must change (a user-visible
    exception class change, for B8's migration guide).
  - `restoreUnknownLogicalTypes` moves out with the converter.
- **M3-15 (visitors to `commonMain`):** the remaining JVM-only bits are `AvroTypeException`, `toBigDecimal` in
  `normalizeNumbers`, and `helpers.kt`'s `capturedKClass.java` fallback. `Char.isLetter` and `isLetterOrDigit` are
  common, but on JS and native their Unicode tables are Kotlin's own; on the JVM they are `Character`'s, as Apache
  used.
- **B8 migration guide:**
  - two different named types with one full name are rejected (point 2);
  - name, prop and reserved-prop errors are `SerializationException`s (point 3);
  - `Avro.schema()`'s default nodes are parser-typed, so `defaultVal()` is non-null for integers (point 4).

## Deviations from the brief

1. **Named-type sharing, and the conflict rejection** (point 2): not in the brief, but needed for the pairing the brief
   relies on. The apache-interop identity test fails without it. The rejection is a behaviour change, flagged for the
   orchestrator.
2. **`avro4kToApacheKeepingUnknownLogicalTypes`** (point 1): an extra internal converter entry point, so that the json
   route does not drop `char` and custom logical types from `Avro.schema()`. The public `toApacheSchema()` is unchanged.
3. **`AvroSchemaCacheTest`**: a one-line internal-API test change, beyond the pin (see "Test changes").
4. **Apache's name and prop validations re-implemented in the visitors** (point 3), to keep generation failures where
   they were, since the json route parses without name validation.
