# M3-11 — Runtime flip behind an Apache facade

**Outcome:** done, in the two commits of the brief's fallback split, each green on `ACC`:
1. `refactor(core): decode on AvroSchema, behind an Apache-typed facade`
2. `refactor(core): encode on AvroSchema, behind an Apache-typed facade` (the one that adds this file).

No locked decision touched. Not api: `core/api/core.api` and `apache-interop/api` are byte-identical
(`git diff --exit-code core/api apache-interop/api` clean after each commit). No new dependency. No benchmark run (the A/B
is M3-11+12 together, per the decomposition).

## What changed, per area

### The facade (`J/AvroDecoder.kt`, `J/AvroEncoder.kt`)

- **`internal interface AvroSchemaDecoder : AvroDecoder { val currentAvroSchema: AvroSchema }`**, implemented by the three
  decoder roots: `AbstractAvroDirectDecoder`, `AbstractAvroGenericDecoder`, `JsonDefaultDecoder`. On the encode side the
  single root `AbstractAvroEncoder` has an `abstract var currentAvroSchema: AvroSchema` (no interface needed).
- **Each root's public `currentWriterSchema`** is now a `final` getter: `apacheFacadeOf(currentAvroSchema)`, i.e.
  `avro4kToApacheKeepingUnknownLogicalTypes` — the identity-cached, two-way-paired converter (M3-05). On a hit it
  returns the caller's own Apache node (a user schema converted at the entry point, or `Avro.schema()`'s node for a
  generated one), so identity and `GenericFixed` semantics hold. The "keeping unknown logical types" variant is used
  (M3-09's open question) so that a node that no Apache node is paired with yet — core's own constants
  (`StringSchema()` map-key schemas) — converts exactly like `Avro.schema()` would, `char` and custom logical types
  included. On a hit both variants are the same lookup.
- **`internal val AvroDecoder.currentAvroSchema` / `AvroEncoder.currentAvroSchema`** extensions: the member for core's
  own coders, `apacheToAvro4k(currentWriterSchema)` for any foreign `AvroDecoder`/`AvroEncoder` (mocks). Every internal
  helper reads these, never the facade: `unsupportedWriterTypeError` (both), `UnexpectedDecodeSchemaError`,
  `ensureFixedSize`, `fullNameOrAliasMismatchError`, `logicalTypeMismatchError`, `namedSchemaNotFoundInUnionError`,
  all the `trySelect*`.
- **Who still reads the facade** (the named intermediate, per value): the built-in serializers' bodies
  (`J/serializer/*.kt`, ~39 `currentWriterSchema` reads), the `@PublishedApi findValueDecoder` behind the public
  `decodeResolving*` (its lambdas take `Schema`), `decodeFixed()` (builds `GenericData.Fixed` with it), the generic
  tree's `GenericData.Fixed`/`EnumSymbol`, and `AnySerializer`'s public hooks on a cache miss. Nothing else.

### Entry-point conversions (once per call, `apacheToAvro4k`, identity-cached)

| Entry point | Where the conversion is |
|---|---|
| `encodeToByteArray`/`encodeToSink`/stream/okio/`AvroSingleObject.encode*`, `encodeWithApacheEncoder` | `AvroInternalExtensions.encodeWithBinaryEncoder` (the one funnel of all of them) |
| `decodeFromByteArray`/`decodeFromSource`/stream/okio/`decodeFromByteBuffer`/`AvroSingleObject.decode*`, `decodeWithApacheDecoder` | `AvroInternalExtensions.decodeWithBinaryDecoder` |
| `AvroObjectContainer` (reader and writer) | per datum, through `encodeWithApacheEncoder`/`decodeWithApacheDecoder`: one identity hit per datum, i.e. per call |
| `encodeToGenericData(writerSchema, …)` / `decodeFromGenericData(writerSchema, …)` | `AvroGenericDataExtensions.kt`, at the construction of the root coder |

A schema from `Avro.schema()` is already paired (`GeneratedSchema`), so the conversion is a hit. The validating wrappers
(`validateSerialization`) keep receiving the Apache schema, unchanged: `ApacheCodecCallSequenceTest` is green unchanged.

### Decoders (commit 1)

- Direct (`AbstractAvroDirectDecoder`, collections, record, record-as-map, value): `currentAvroSchema` var, every `when`
  on the stored `AvroSchema.type`, `types[readIndex()]` for unions, `enumSymbols[readEnum()]` for enums (M3-04), the
  common `AvroBinaryDecoder.skip(AvroSchema)` for skipped writer fields (the private Apache-typed skip is deleted),
  `StringSchema()` constants for map keys.
- `AbstractPolymorphicDecoder`: name lookup by `fullName`, then (on a miss only) the aliases of a `NamedSchema` iterated
  directly — no `Set<String>` built per value as Apache's `getAliases()` did.
- Generic tree (deprecated, moving to `apache-interop`): values carry their own Apache schemas (`GenericArray.schema`,
  `GenericContainer.schema`, `IndexedRecord.schema`), converted with `apacheToAvro4k` — **one identity lookup per record
  or array value**, accepted on this unbenchmarked, deprecated path.
- `JsonDefaultDecoder`: `AvroSchema` throughout, `logicalTypeName` for the char rule; `decodeFixed()` still returns
  `GenericData.Fixed`, built with the facade (`currentWriterSchema`), i.e. the paired reader-schema node (M3-08's handoff).

### Encoders (commit 2)

- `AbstractAvroEncoder` and every subclass: `currentAvroSchema`; unions through the common helpers (`isUnion`, `types`,
  `getIndexTyped` with `< 0` checks); `isFullNameOrAliasMatch(descriptor)` is a one-line inline jvmMain delegate to the
  common helper (M3-07's handoff), so no bound reference is allocated.
- **Enum:** `EnumSchema.getSymbolIndexOrNull(symbol)`, one hash lookup, instead of Apache's `getEnumOrdinal` in a
  `try/catch`. An unknown symbol still throws (see Deviations).
- Record encoders hold the `RecordSchema` (one cast per record, not a per-field `fields` accessor);
  `MissingFieldsEncodingException` is built with its public `String` constructor, same message shape.
- Generic encoders: `GenericData.Array`, `ListRecord`, `GenericData.Fixed`, `GenericData.EnumSymbol` get their Apache
  node through the paired `apacheFacadeOf` / facade — a lookup per value, accepted on this deprecated path.
- `trySelectLogicalTypeFromUnion` now has the 1-type and 2-type overloads (no `vararg` array per call);
  `trySelectNamedSchema(descriptor)` reads the descriptor's aliases only on a name miss (it used to allocate
  `descriptor::aliases` per call).
- Commit 1's intermediate (encoders looking each record's Apache writer schema up with `apacheToAvro4k` to resolve the
  workflow) is removed.

### `RecordResolver`, `AvroDefaults.kt`, `PolymorphicResolver`

- `resolveFields(writerSchema: AvroSchema, …)`. The **outer `fieldCache` level is a `WeakIdentityKeyCache<AvroSchema,
  IdentityFirstCache<…>>`**, read with `getOrNull(k) ?: getOrPut(k) { IdentityFirstCache() }`; the 16-entry inline memo is
  retyped to `AvroSchema` (identity, unchanged logic).
- Writer ↔ reader fields: `RecordSchema.getFieldIndexOrNull` (name, then each descriptor alias), **once per (writer,
  descriptor) pair**, inside the workflow computation; the old per-field `aliases()` scans and `Field.pos()` are gone.
  The reader schema is `avro.avroSchema(descriptor)` (same cache entry as `schema()`).
- `AvroDefaults.kt`: the Apache-typed `toFieldDefault(Schema)`, `isValidDefaultFor(Schema)`, `resolveDefaultBranch(Schema)`
  and `Schema.Type.toAvroSchemaType()` are deleted (M3-09's handoff); one rule definition remains. The char rule reads
  `logicalTypeName` (it already did on the `AvroSchema` side). `helpers.kt`'s `Schema.asSchemaList()` is deleted;
  `Schema.Type.toAvroSchemaType()` moved to `helpers.kt` as the bridge for the serializers' Apache-typed helper calls.
- `PolymorphicResolver`'s name resolver reads `avroSchema(it).fullName`.

### `AnySerializer`

`decodingCache` is a `WeakIdentityKeyCache<AvroSchema, DeserializationStrategy<Any>>`, read with the
`getOrNull ?: getOrPut` pattern; the key is the decoder's `currentAvroSchema`. The configured logical types are matched on
`logicalTypeName` (M3-09's handoff). The protected Apache-typed hooks are unchanged; on a miss they receive
`decoder.currentWriterSchema` (the facade), which is cold.

### Converter (`J/internal/AvroSchemaApacheConversion.kt`) — not in the brief, needed by the oracle

Every Apache schema an entry point receives is now converted, so a schema Apache accepts and the model rejects would now
fail where it used to work. Confluent's `ReflectKSerializerTest` found one: a record listing **its own full name as an
alias** (`copy(name = "ns.theRecord")` of a record aliased `ns.theRecord`). The model rejects it (`Record name … cannot be
part of aliases`); Apache accepts it, and it is a no-op. The converter now drops such self-aliases (records, enums, fixed,
and a field listing its own name). Pairing is unaffected (the reverse conversion of such a node is a pairing hit). Pinned by
a new `apache-interop` test. Other model-only rejections (e.g. a field alias equal to *another* field's name, which is
genuinely ambiguous) stay rejected; none is exercised by any suite.

## Hit paths, allocation-free (`javap -c`, commit 2's classes)

- `AnySerializer.deserialize`: `getCurrentAvroSchema` → `WeakIdentityKeyCache.getOrNull$core` → `ifnonnull` straight to
  `decodeSerializableValue`. The `invokedynamic` (the capturing lambda) and `getOrPut` are only on the null branch.
- `RecordResolver.resolveFields`: the inline memo loop (`if_acmpne` ×2, `areturn`); then `fieldCache.getOrNull$core` →
  `ifnonnull` past the (non-capturing, singleton) `invokedynamic`; then `IdentityFirstCache.getOrPut` inlined:
  `identity.getOrNull$core`, `equality.getOrNull$core`, compute only on the miss. No `new` before a miss.
- The facade's hit (`avro4kToApache…`): `apacheByAvro4k.getOrNull` + `Link.get()` (one extra dereference), as measured
  shape in M3-05. That is the per-value cost the serializers pay until the public flip.

## M3-07's four semantic gaps — decisions

1. **Union naming in messages:** every message naming the writer schema uses `fullNameForMessages` (`union[a, b]`, as
   Apache).
2. **Schemas in messages:** `toSchemaJsonString()` everywhere a schema was interpolated. `GenericDataMapEncodingTest:198`
   passes unchanged. For named types the key order differs from Apache's `toString()` (model serializer's order); no test
   pins such a message.
3. **Logical types — guarded.** The specification says an implementation must ignore an invalid logical type and use the
   underlying type; Apache's `getLogicalType()` is null for it. Accepting the raw prop would have regressed real cases:
   `[{"type":"fixed","size":8,"logicalType":"uuid"},"string"]` used to encode a `UUID` as the string branch and would
   have failed on the fixed size; a `decimal` branch without `precision` would have failed in the serializer instead of
   falling back to a string branch. So the new common `AvroSchema.hasValidLogicalType()` (in `AvroSchemaHelpers.kt`)
   mirrors Apache 1.12's `LogicalTypes.fromSchemaIgnoreInvalid(s) != null` for the specification's names (decimal
   precision/scale/fixed capacity, uuid on string or fixed(16), duration on fixed(12), big-decimal on bytes, the date/time
   types on int/long, and the Java-binding-prop incompatibility); any other name (avro4k's `char`, custom ones) stays
   valid, as avro4k resolves logical types by name. `trySelectLogicalTypeFromUnion` skips invalid branches. The common
   `getIndexLogicallyTyped` itself is unchanged (its differential test pins it as documented). New
   `LogicalTypeUnionSelectionTest`: a differential test of `hasValidLogicalType` against Apache over 38 schemas, plus
   both union cases above encoded byte-for-byte as Apache. **For M3-12:** the serializers' own
   `logicalType?.name == …` checks become `logicalTypeName == …` there; they must use the same guard, or the check moves
   into the model.
4. **`getIndexTyped(RECORD)`:** no runtime call site asks for a named type (records, enums and fixed are selected by name,
   size or symbol), so the type-lookup semantics is never observable. Nothing to do.

## Structural equality

Grep of every added line in `core/src/{jvm,common}Main` for `==`, `!=`, `indexOf`, `contains`, `in`: every hit compares
an `Int`, a `String` (names, `logicalTypeName`, json keys), or an `AvroSchema.Type` enum constant (identity equals). One
`Name != Name` in the converter's self-alias filter (cold, per conversion; `Name.equals` is a `String` compare). No `==`,
`indexOf`, `contains` or equality-hashed key on an `AvroSchema` or a `Field` remains in runtime code: the two caches keyed
by schemas are identity caches, the inline memo compares with `===`.

## Shared state

The two retyped caches are `WeakIdentityKeyCache`s (CAS copy-on-write, M3-06/B6); the inline memo is unchanged
(immutable array, volatile publication). Per-operation state stays on the coder of one call.

## For the public-API flip (M3-12)

- Delete the facade: `apacheFacadeOf`, the `final override val currentWriterSchema` getters, the `AvroSchemaDecoder`
  interface (or make `currentWriterSchema: AvroSchema` the member), and the `currentAvroSchema` extensions' foreign-coder
  fallback.
- The serializers read `currentWriterSchema` (then `AvroSchema`); the Apache-typed helper overloads kept for them go:
  `unsupportedWriterTypeError(Schema.Type…)` ×2, `trySelectTypeNameFromUnion(Schema.Type)`,
  `trySelectLogicalTypeFromUnion(String, Schema.Type[, Schema.Type])`, `logicalTypeMismatchError(String, Schema.Type)`,
  `UnexpectedDecodeSchemaError(…, Schema.Type…)`, `Schema.isFullNameOrAliasMatch(String, …)`, `Schema.isFullNameMatch`,
  `Schema.nonFailingAliases`, `Schema.Type.toAvroSchemaType()`. Their logical-type checks must use `hasValidLogicalType`
  (gap 3).
- `decodeFixed()` / the generic `GenericData.*` values stop using the facade.
- `AnySerializer`'s hooks take `AvroSchema`: pass the key directly instead of `decoder.currentWriterSchema`.
- The entry points' `apacheToAvro4k` become no-ops (the parameter is `AvroSchema`); `AvroObjectContainer` then converts
  once per file in `setSchema`.
- `MissingFieldsEncodingException`'s public constructors take `AvroSchema` fields (the runtime already uses the `String`
  one).
- **Watch in the A/B:** the facade is now on the per-value path of every serializer read (`currentWriterSchema`); the
  decimal guard reads two props per union selection of a decimal; a caller creating a fresh Apache writer schema per
  call now misses two identity caches (converter, `fieldCache`), where the old `fieldCache` hit by equality.

## Deviations from the brief

1. **Converter leniency for self-aliases** (see above). Needed for Confluent's suite to pass unchanged; a converter
   change, no API change. Flagged for the orchestrator.
2. **Gap 3 guarded, not accepted**, with a new common helper `hasValidLogicalType` (reasons above).
3. **An unknown enum symbol still throws on encode**, rather than M3-04's "fall back to the default symbol": the enum's
   `default` is for a *reader* resolving an unknown writer symbol; writing it in place of the value would silently change
   the data. Apache's writer throws too, and `EnumTest` pins it (the mutation above).
4. **`SchemaGenerationTest`** is changed although not listed in the brief: it called the Apache-typed default rules the
   brief says to delete.
5. **`AvroObjectContainer` converts per datum** (an identity hit), not once per file: its datum writer/reader call the
   public Apache-typed entry points; converting in `setSchema` needs an internal `AvroSchema`-typed entry, which M3-12's
   signatures give for free.
