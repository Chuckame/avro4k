## 1. Fresh-but-equal writer schemas (commit 1)

**Problem (PROGRESS decision log 2026-09-25, M3-11).** A caller that hands in a writer schema that is fresh but equal
on every call (parsed per message, a registry lambda that re-parses) missed every identity-only cache: the entry-point
conversion `apacheToAvro4k`, `RecordResolver.fieldCache`'s outer level, `AnySerializer.decodingCache`. Each call
re-resolved the workflows and seeded every node of the fresh schema into the copy-on-write identity tables.

**Design — identity first, equality behind, only the canonical instance seeded** (`IdentityFirstCache`'s rule, M3-06):

| Cache | Before | After |
|---|---|---|
| `RecordResolver.fieldCache` outer level (writer schema) | `WeakIdentityKeyCache` | `IdentityFirstCache<AvroSchema, IdentityFirstCache<SerialDescriptor, …>>`; the inline memo (identity, 16 entries) unchanged in front |
| `AnySerializer.decodingCache` | `WeakIdentityKeyCache` | `IdentityFirstCache<AvroSchema, …>` (inline `getOrPut`: no lambda per call) |
| `apacheToAvro4k` (cached converter, behind apache-interop's public `Schema.toAvro4k()`) | identity only (two-way pairing) | identity pairing, then a new equality layer `avro4kByEqualApache: WeakKeyCache<Schema, AvroSchema>` holding **only the roots whose conversion was seeded**; an equal fresh input returns the canonical conversion without walking or seeding anything |
| `AvroSingleObject.fingerprintCache` (commit 2, as it became `AvroSchema`-keyed) | `WeakKeyCache<Schema,…>` (equality) | `IdentityFirstCache<AvroSchema, ByteArray>` |

**Semantics, documented in the KDoc** (`toAvro4k()`, `apacheToAvro4k`, `RecordResolver.fieldCache`): for an Apache
schema that is equal to an already converted one but a different instance, `toAvro4k()` returns the canonical
conversion, and `toAvro4k().toApacheSchema()` returns the **canonical** Apache instance, not the caller's. Equality is
Apache's (`Schema.equals`) and the model's, which both ignore docs and (record/field) aliases: two writer schemas that
differ only by aliases share the workflow of the first one. That is exactly the pre-M3-11 behaviour (the old
`fieldCache` was keyed by Apache equality), now documented.

**Cost of the equality path.** Only on an identity miss. `AvroSchema.hashCode`: a record hashes its name (O(1)); a union
the list of its branches' hashes (records → names); arrays/maps their props + element hash; primitives their props;
enum/fixed are data classes (name, symbols/size, doc, aliases, props) — all flat, no record recursion. `equals` then
walks the schema once (cycle-safe). Apache's `Schema.hashCode` is cached per instance after its first computation.
So a fresh schema costs one hash + one structural equals per call at the call boundary, and per record-node lookup in
`fieldCache` on the inline memo's miss (the memo is identity: a fresh schema's nodes enter it once per call, bounded at
16 entries).

**Bounded tests** (`T/FreshWriterSchemaCacheTest.kt`, 4 tests, `CALLS = 10_000`, each call checks the sizes so a leak
fails at the first call that grows a cache):
- 10,000 Apache schemas parsed per call, each encoded and decoded: both identity conversion tables and the equality
  layer keep their size, the workflow cache's identity and equality layers keep theirs (the workflow is resolved once);
  plus `fresh.toAvro4k() === first.toAvro4k()` and `fresh.toAvro4k().toApacheSchema() === first` (the documented semantics).
- 10,000 `AvroSchema.fromJsonString` per call into `resolveFields`: same workflow instance, layers at 1/1.
- 10,000 per call through `AnySerializer`: `decodingCache` layers fixed.
- Two different schemas with the same record name (same hash bucket) alternately, fresh each time: each decodes and
  encodes with its own workflow (1 vs 2 decoding steps); `narrow != wide`, same `hashCode`.

**Mutations (each applied, `:core:jvmTest --tests '*FreshWriterSchemaCacheTest*'`, reverted):**

| Mutation | Result (fast failure) |
|---|---|
| converter: drop the equality lookup | `call 0 grew the conversion caches: 30 > 20` |
| `fieldCache` outer level identity-only | `expected:<1> but was:<0>` (equality layer empty) |
| `fieldCache` seeding every fresh instance in both layers | workflow `should be the same reference` |
| `decodingCache` identity-only + seeding | `call 0 grew the decoding cache of AnySerializer` |

**Test changed:** `T/internal/RecordResolverTest.kt` "two structurally equal but distinct schema instances…" pinned
M3-11's identity-only contract (an equal copy gets its own workflow); it now pins the restored one (same workflow).

## 2. The flip (commit 2)

### Facade deleted (M3-11's "For the public-API flip" checklist)
- `apacheFacadeOf`, the `AvroSchemaDecoder` interface, the `currentAvroSchema` extensions' foreign-coder fallback
  (`apacheToAvro4k(currentWriterSchema)`), `GeneratedSchema` (`Avro.schemaCache` now holds the `AvroSchema` directly;
  `schema()` is one lookup, with no eager Apache form: the Apache form is computed on demand by `toApacheSchema()`).
- The roots' `currentWriterSchema: AvroSchema` is a final getter over the internal `currentAvroSchema` field
  (`AbstractAvroDirectDecoder`, `AbstractAvroGenericDecoder`, `JsonDefaultDecoder`, `AbstractAvroEncoder`); helpers read
  `currentWriterSchema` directly (interface call, no lookup).
- Deleted Apache-typed helper overloads: `unsupportedWriterTypeError(Schema.Type…)` ×2, `trySelectTypeNameFromUnion(Schema.Type)`,
  `trySelectLogicalTypeFromUnion(String, Schema.Type[, Schema.Type])` (retyped), `logicalTypeMismatchError(String, Schema.Type)`
  (retyped), `UnexpectedDecodeSchemaError(…, Schema.Type…)` (retyped), `Schema.isFullNameOrAliasMatch`, `Schema.isFullNameMatch`,
  `Schema.nonFailingAliases`, `Schema.Type.toAvroSchemaType()`. `avro4kToApacheKeepingUnknownLogicalTypes` is merged into
  `avro4kToApache` (see §2.4).
- `decodeFixed()` returns the bytes; the generic tree's `GenericData.Fixed`/`EnumSymbol`/`Array`/`ListRecord` get their
  Apache node from `avro4kToApache` (identity-cached, per value, on that deprecated path only).
- `AnySerializer`'s hooks receive the `AvroSchema` key itself.
- Entry points take `AvroSchema`; the per-call `apacheToAvro4k` is gone from them. `encodeWithApacheEncoder`/
  `decodeWithApacheDecoder` (`@InternalAvro4kApi`, Apache callers) keep their Apache signature and convert once per
  call; new **internal** 4-argument overloads take both forms. `AvroObjectContainer`'s datum writer/reader convert once
  per file in `setSchema` (M3-11 deviation 5 closed); `openWriter` converts its `AvroSchema` once for Apache's header.

### Logical types in the serializers — `knownLogicalTypeName` (M3-11 gap 3)
The serializers compared `schema.logicalType?.name` (Apache: null for an invalid or unknown logical type). New common
internal `AvroSchema.knownLogicalTypeName`: the `logicalType` prop when it is one of the specification's 13 names **and**
`hasValidLogicalType()`, else null; memoized per instance (`AvroSchema.knownLogicalTypeNameMemo`, an internal racy
single-check field, immutable values — a field read per value after the first). Used by every `when (… logicalType?.name)`
and by `trySelectLogicalTypeFromUnion` (replacing its `logicalTypeName == x && hasValidLogicalType()` pair). Tests:
`LogicalTypeUnionSelectionTest` now also asserts `knownLogicalTypeName == LogicalTypes.fromSchemaIgnoreInvalid(s)?.name`
over its 38 schemas, plus a `char`/custom case; `AvroSchemaHelpersTest` (common) gets one test.
**Behaviour note:** for a `char`/custom logical type, Apache's `getLogicalType()` on a *parsed* schema is null; M3-11's
facade restored it as a `LogicalType` object on *generated* schemas. `knownLogicalTypeName` follows the parsed-schema
semantics everywhere, so e.g. `LocalDate` now decodes an `int` whose logical type is `char` (it used to refuse on a
generated schema only). No test pins the old asymmetry.

### `BigDecimalSerializer` in plain `java.math` (pulled forward from the serializers-for-common unit)
Keeping Apache's `Conversions` would have needed an Apache schema and a `LogicalTypes.Decimal` **per value**. The
`decimal` (bytes and fixed) and `big-decimal` bytes are rewritten after Apache 1.12.1's `DecimalConversion` /
`BigDecimalConversion` sources, same validation and **same `AvroTypeException` messages** (Apache's exception class
kept until Apache leaves core); `@AvroDecimal`'s schema gets Apache's `addToSchema` props and validation messages.
New `T/encoding/DecimalBytesDifferentialTest.kt` (3 tests): 17 values × 4 schemas (bytes, fixed 8, fixed 16, bytes
38/6) byte-for-byte and value-for-value against Apache's conversions; the scale/precision failures with the same
messages; `big-decimal` over 19 values.

### Other body changes
- `AvroSerializer.kt`: `AvroSchemaSupplier.getSchema(): AvroSchema`; `getAvroSchema` is now `getSchema` (no conversion);
  internal helpers `logicalTypeSchema(type, name, props…)` and `AvroSchema.withLogicalType(name, props…)` replace
  `Schema.create(…).copy(logicalType = LogicalType(x))` (props in Apache's order: `logicalType` then extra props).
  `AvroFixed.createSchema` builds a `FixedSchema` (inline value class: aliases relative to the fixed's namespace, a
  self-alias dropped as the model rejects it — Apache accepted it as a no-op).
- `AvroDuration.DURATION_SCHEMA`: a getter building a new `FixedSchema` per read (a generated node is never shared).
- `MissingFieldsEncodingException`'s schema constructors take `List<RecordSchema.Field>` + `AvroSchema`; message uses
  the model's json (`toSchemaJsonString`) — key order of named types may differ from Apache's `toString()`. The record
  encoder now uses this public constructor again.
- `AvroSingleObject`: registry lambda returns `AvroSchema?`; fingerprint via Apache's `SchemaNormalization` on the
  **uncached** conversion, on a cache miss only (M3-10's common fingerprint is the Apache-exit unit's job).
- Validation (`validateSerialization`): `encodeWithValidation`/`decodeWithValidation` convert the `AvroSchema` with the
  cached `avro4kToApache` per call (identity hit for generated or converted schemas).

### 2.4 `toApacheSchema()` keeps unknown logical types
`avro4kToApache` (behind apache-interop's public `toApacheSchema()`) now always restores logical types Apache does not
know (`char`, custom), as `Avro.schema()`'s Apache form did in v2 and until now. Without it, the oracle suite's
`Avro.apacheSchema<T>()` (now `schema<T>().toApacheSchema()`) would lose them. Documented in its KDoc.

## 3. Generic-data decision
`encodeToGenericData` / `decodeFromGenericData` (deprecated, moving to apache-interop later) **keep their Apache-typed
public signatures**: they produce and consume Apache `GenericData` values, which carry Apache schemas, and they move to
the Apache module, where Apache types are the point. Flipping them now would be flipped back there. Internally they
convert once per call (`apacheToAvro4k`); `encodeToGenericData<T>(value)` uses `avro4kToApache(schema(serializer))`.
`ListRecord` / `Record` unchanged (Apache).

## 8. Structural equality and shared state
Every added `==`/`!=`/`in` in `core/src/{jvm,common}Main` and Confluent main compares a `String`, an `Int`, a `Name`
or an enum constant. The deliberate equality layers (§1: `fieldCache`, `decodingCache`, `fingerprintCache`,
`avro4kByEqualApache`) run only on an identity miss. Shared state: all caches CAS copy-on-write; the memo field is an
immutable-value racy single check; per-operation state on the coder of one call.
