## 1. Changes per item of the brief

1. **Serial names** — `X::class.qualifiedName` does not even compile on Kotlin/JS ("This reflection API is not
   supported in Kotlin/JS", found by the dry run), so *every* use in a moving file was removed, not only the `!!` ones:
   - serial names and messages about a **static** class → the literal it evaluates to on the JVM (table below);
   - messages about a **runtime** class (`this::class`, `value::class`, the `KClass`es of `BadDecodedValueError`) → a new
     internal `KClass<*>.nameForMessages`, `qualifiedName.toString()` on the JVM (byte-identical: a string template
     printed a null qualified name as `null`; the former `!!` sites now print `null` instead of throwing an NPE, for an
     anonymous class only — unreachable in practice). On JS it will be `simpleName` (§6).
   - The count, in moving files: 7 serial-name sites (`qualifiedName!!` as a descriptor name or error type name), 4
     static-class message sites (5 references), 11 runtime-class references in messages (9 in `exceptions.kt`, 2 in
     `AvroSerializer.kt`). The Java serializers keep theirs (JVM files).
2. **Exact arithmetic** (`KotlinInstantExtensions.kt`): private `multiplyExact`/`addExact` with `Math.*Exact`'s
   algorithm and `ArithmeticException("long overflow")` (same class, same message, still wrapped in the same
   `SerializationException`); `Math.floorDiv`/`floorMod` → `Long.floorDiv`/`Long.mod` (common stdlib, same results).
   **`AvroDuration`**: `ByteBuffer` little-endian → manual packing of three 32-bit little-endian ints, byte-identical.
3. **`AnySerializer`** split: `J/serializer/AbstractAnySerializer.kt` (moves; `@InternalAvro4kApi public abstract class
   AbstractAnySerializer internal constructor() : KSerializer<Any>`: descriptor, `nullable`, `decodingCache`,
   `deserialize`, every `resolve*`/`preResolve*` hook, and `AnyTypeSerializersModule`); `J/serializer/AnySerializer.kt`
   (stays, becomes the JVM actual) keeps exactly today's `ConcurrentHashMap<Class<out Any>, …>`, `serialize`, the
   `Class`-based inference and the `Class`-typed `protected open inferSerializationStrategyFromNonSerializableType`.
   Confluent's 72 tests pass unchanged. `apiCheck` clean (both classes are `@InternalAvro4kApi`). The non-JVM actual
   needs a source set that does not exist yet, so it is written in step B (§6, verified by the dry run).
4. **`helpers.kt`**: `capturedKClass?.java?.let(serializersModule::serializerOrNull)` → `capturedKClass?.serializerOrNull()`
   (kotlinx-serialization, common, `@InternalSerializationApi`). The module's contextual lookup already ran just before
   (`getContextualDescriptor`), so the fallback is the class's own (generated or built-in) serializer in both versions.
   The Apache-typed `Schema.copy` / `Schema.Field.copy` (internal API, used by Confluent's tests) moved to a new
   `J/internal/ApacheSchemaCopy.kt`, same package (so its JVM facade is now `ApacheSchemaCopyKt`, internal API only).
5. **Apache exceptions**: `ClassVisitor`'s invalid field default now throws `AvroSchemaGenerationException` (internal,
   a `SerializationException`) with the same message instead of Apache's `AvroTypeException`; `AvroDefaultSchemaTest`
   now expects `SerializationException` and pins both messages. Appended to `b8-migration-items.md`. No other Apache
   type is left in a moving file (the grep in §4); `JsonDefaultDecoder.decodeValue()`'s `GenericData.Fixed` went behind
   a JVM hook (item 7).
6. **`validateSerialization`**: the validating wrap is behind `AvroBinaryEncoder.validatingAgainst(writerSchema)` /
   `AvroBinaryDecoder.validatingAgainst(writerSchema)` (JVM: Apache's validating encoder/decoder through the cached
   converter, exactly as before). The flag check stays in common code (`J/internal/AvroCodecEntryPoints.kt`, moves: the
   former `encodeWithValidation`/`decodeWithValidation` + the two codec entry points, now `internal`). The Apache entry
   points (`encodeWithApacheEncoder`/`decodeWithApacheDecoder`) stay in `AvroInternalExtensions.kt` (same JVM facade
   `AvroInternalExtensionsKt`, Confluent unchanged). Platform difference documented in
   `AvroConfiguration.validateSerialization`'s KDoc and in `b8-migration-items.md`.
7. **Platform defaults** — one JVM file, `J/internal/Platform.jvm.kt` (stays; B adds `actual`):
   `defaultSerializersModule()` (all four modules, same order as before), `defaultLogicalTypes()` (the former map
   verbatim, a new map per call as before), the two `validatingAgainst`, and `genericFixedValue(schema, bytes)` (the
   deprecated `decodeValue()` of a fixed default: `GenericData.Fixed` on the JVM). `Avro.Default` and
   `AvroConfiguration.logicalTypes`'s default call them; their KDoc and `AvroBuilder.setLogicalTypeSerializer`'s list
   say what differs by platform. The six date/time logical type names moved from `JavaTimeSerializers.kt` (stays) to a
   new `J/serializer/LogicalTypeNames.kt` (moves), as the Kotlin `Instant` serializer uses them.
8. **`@Volatile`**: `RecordResolver.inlineCache` is now `kotlin.concurrent.Volatile` (a typealias of the JVM one on the
   JVM: same bytecode). The only one in a moving file. **Native publication argument** (also in its KDoc): the array
   and every `Memo` in it are fully built before the single write that publishes the array, and never mutated
   afterwards. On the JVM a volatile write happens-before every read that observes it (JLS 17.4.5); on Kotlin/Native,
   `kotlin.concurrent.Volatile`'s stdlib contract is that a thread reading the value "sees not only that value, but all
   side effects that led to writing that value" — so a reader that sees the array sees complete `Memo`s, without the
   JVM final-field guarantee that native lacks (which would not cover array elements anyway). JS is single-threaded. A
   lost concurrent update only costs a future miss into `fieldCache`. Same argument as `RecordSchema`'s field index and
   `CopyOnWriteWeakTable`'s atomic.
9. **Move list**: §5.

```kotlin
@InternalAvro4kApi
public actual open class AnySerializer actual constructor() : AbstractAnySerializer() {
    private val encodingCache = WeakKeyCache<KClass<out Any>, SerializationStrategy<Any>>()

    actual override fun serialize(encoder: Encoder, value: Any) {
        val type = value::class
        val serializer = encodingCache.getOrNull(type) ?: encodingCache.getOrPut(type) { encoder.serializersModule.inferSerializationStrategy(value) }
        encoder.encodeSerializableValue(serializer, value)
    }

    @OptIn(InternalSerializationApi::class, ExperimentalSerializationApi::class)
    @Suppress("UNCHECKED_CAST")
    private fun SerializersModule.inferSerializationStrategy(value: Any): SerializationStrategy<Any> {
        val type = value::class
        // the JVM's order: the class's own serializer, then the module's contextual one
        (type.serializerOrNull() ?: getContextual(type))?.let { return it as SerializationStrategy<Any> }
        if (value is Collection<*>) return ListSerializer(this@AnySerializer.nullable) as KSerializer<Any>
        if (value is Map<*, *>) return MapSerializer(this@AnySerializer.nullable, this@AnySerializer.nullable) as KSerializer<Any>
        return inferSerializationStrategyFromNonSerializableType(type) as SerializationStrategy<Any>?
            ?: throw SerializationException("Cannot find serializer for type $type. Please register a serializer for this type in the serializers module.")
    }

    @InternalAvro4kApi
    protected open fun SerializersModule.inferSerializationStrategyFromNonSerializableType(type: KClass<out Any>): SerializationStrategy<*>? = null
}
```

## 9. Open points

1. **Non-JVM defaults** (§6) are a proposal on the brief's "the Kotlin ones only": `duration`, plus `uuid` →
   `KotlinUuidSerializer` and `timestamp-millis`/`-micros` → `KotlinInstantSerializer`. Veto → `duration` only (and fix
   `Avro.kt`'s KDoc).
2. **Native `AnySerializer.encodingCache`**: the planned common `WeakKeyCache` keys on `value::class`. If Kotlin/Native
   allocates a fresh `KClass` per `::class` (to check), nothing else holds the stored key, so it can be collected at the
   next GC and every such collection costs a re-insert (O(capacity) copy). Class keys are bounded, which is why the JVM
   uses a strong map; a strong, CAS-published copy-on-write map would be the platform-neutral equivalent. Not measured.
3. **Non-JVM `AnySerializer` inference** cannot pass type-argument serializers (no `Class.typeParameters` without
   reflection): a generic serializable class (e.g. `Pair`) that is not a `Collection`/`Map` is not inferred on js/native.
4. **`validateSerialization`** is ignored off the JVM until the common validating codec exists; documented.
5. **`@Language`** could come back through a common `expect annotation class` if IDE injection is missed; not worth a
   split-package annotation now.
6. `normalizeDecimalNumber` accepts ASCII digits only, where `BigDecimal` also accepts other Unicode decimal digits; a
   json default cannot produce them except as an unquoted token, which then fails in both (with different messages).
7. `encodeToByteArray()` on JS/native replaces a lone surrogate with U+FFFD (the JVM with `?`), for a string default read
   as bytes; JVM unchanged.
