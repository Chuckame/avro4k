## Rejected, and why

- **`fingerprintCache` → `WeakIdentityKeyCache` (the brief's wording): not done; it stays an `IdentityFirstCache`,
  still per instance.** The brief predates M3-12, which already made it `IdentityFirstCache<AvroSchema, ByteArray>`
  (a `WeakIdentityKeyCache` in front of a `WeakKeyCache`) to fix the regression recorded in the decision log on
  2026-09-25: a writer schema the caller creates per call (re-parsed per message) must hit by equality and never be
  seeded by identity, or every call inserts into, and copies, a growing copy-on-write table. A pure identity cache
  would bring that back. The fingerprint itself is now cheap (no conversion, no json parse), but the per-call insertion
  is the cost the rule is about. `AvroSingleObjectFingerprintCacheTest`'s "distinct but structurally equal schema"
  test is green either way; it does not bound the table size.
- **Making toAvro4k()/toApacheSchema() the implementation and deleting `apacheToAvro4k`/`avro4kToApache`:** not done.
  Those internal names are used by core's tests (`SchemaGenerationTest`, the test bridges) next to their uncached and
  cache-size siblings; the public functions stay one-line delegates, now within their own module.
- **Splitting `ReadBytesBufferBoundsTest`** to move its one adapter test: not worth a new file; it runs unchanged.
- **Exception class:** the existing internal error factories (`exceptions.kt`) are decoding errors; a plain
  `SerializationException` was used, no new type (the exception hierarchy is a later unit).
