## Fixed (introduced by M3)

| # | Where | Defect | Fix | Test |
|---|---|---|---|---|
| 1 | `KotlinxIoEncoder.writeString`, `AbstractAvroEncoder` (String → bytes/fixed), `JsonDefaultDecoder` (string default read as bytes) | **New cross-platform divergence**: Kotlin's `encodeToByteArray()` writes an unpaired surrogate as `?` on the JVM (`getBytes(UTF_8)`, so Apache too) but as U+FFFD (3 bytes) on JS and native: `"a\uD800b"` was `06 61 3F 62` on the JVM, `0A 61 EF BF BD 62` elsewhere | `String.encodeToUtf8()` (`expect`): the JVM keeps `encodeToByteArray()`; JS/native scan once and use `encodeToByteArray()` when there is no unpaired surrogate (the usual case, same bytes), else encode by hand with `?` — the same rule as the fingerprint's CRC encoder (M3-10) | `KotlinxIoCodecTest` (6 strings, bytes pinned, all platforms) |
| 2 | `AbstractAnySerializer.resolveDeserializationStrategy` | Looked up `AvroConfiguration.logicalTypes` with the raw `logicalType` prop: an invalid specification logical type (`uuid` on a fixed of 8, `duration` on a fixed ≠ 12, `decimal` without precision) picked the logical type's serializer, which then threw, and the strategy is cached per writer schema. Before M3, Apache's `getLogicalType()` ignored it | `AvroSchema.configuredLogicalTypeName`: a specification name only when valid (`knownLogicalTypeName`), any other name (avro4k's `char`, a user's custom one) as is | `GenericUuidTest` (invalid `uuid` fixed → `ByteArray`; custom name → its serializer) |
| 3 | `RecordResolver` / `SerializationWorkflow.missingElements` (record defaults, M3-08) | The `lazy` initializer captured the class descriptor, which keys the workflow **weakly** in the resolver's cache: the value kept its own key alive, so a descriptor (its serializer, its class loader) was never released | A `@Volatile` memo on the workflow, filled by `RecordResolver.missingElements(workflow, descriptor)` from the caller, which has the descriptor; same publication rule (array complete before the write) | `RecordResolverTest` (two fresh descriptors, with and without missing elements computed, collected after leaving the inline cache) |
| 4 | `apacheToAvro4k`'s equality fallback (M3-12) | Apache's `EnumSchema.equals`/`hashCode` ignore `enumDefault` (checked in the 1.12.2 sources); the model's `EnumSchema` (a data class) does not. A schema equal to an already converted one but for an enum default got the canonical conversion: its default silently lost, and `toApacheSchema()` returned the other instance | On an equality hit, `enumDefaultsMatch` walks both trees (records once each) and falls through to a real conversion if any enum default differs; the canonical entry stays. Cost: one tree walk per equality hit, next to Apache's own `equals` walk | `AvroSchemaApacheIdentityTest` |
| 5 | `KotlinGenerator.generateKotlinClasses` | Converted freshly parsed schemas with the **cached** converter (the "fresh schema → uncached converter" rule): in a long-lived Gradle daemon, an `.avsc` edited only in a doc, an alias or an enum default could generate from the previous run's equal schema | `apacheToAvro4kUncached(schema)` | `KotlinGeneratorTest` (doc changed between two equal schemas) |
| 6 | Schema generation (`toSchemaAliases`, `ClassVisitor` field aliases) | `@AvroAlias("Foo")` on a record, enum or field named `Foo` threw (the model rejects an alias equal to the name); before M3 generation built Apache schemas, whose `addAlias` accepts it. The Apache conversion and `AvroFixed` already drop it | Dropped at generation, like `AvroFixed` and the Apache conversion. The model's own JSON parser still rejects it (deliberate strictness, unchanged) | `AvroAliasSchemaTest` |

Every test above was mutation-checked: with the fix reverted (or, for 3, the workflow made to hold its descriptor
again), the test fails.
