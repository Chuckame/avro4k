# M3-18 — common validating codec

**Outcome:** done. Not api (`core.api` and `apache-interop.api` byte-identical). No locked decision touched, no public
name or shape changed.
**Commits:** see `git log -- docs/plans/notes/m3-18.md` and the `feat(core): validate serialization on every platform`
commit before it.

## What was built

All in `core/src/commonMain/.../internal/codec/`, `internal`:

- **`WriterSchemaCallValidator`** — the state machine shared by both sides. An explicit stack of what is still
  expected, as parallel arrays (`IntArray` kinds, `Array<AvroSchema?>`, `Array<String?>` labels, two `LongArray`
  counters), allocated once per validated datum and doubled on deep nesting. Entry kinds:
  - `VALUE(schema)`: one value. A record is replaced by its fields (first on top) lazily when it reaches the top, above
    a `RECORD_END` marker that only remembers the record's place for error paths; so recursive schemas need no
    pre-walk. A union expects its index, then the entry becomes the chosen branch.
  - `MAP_KEY`: a string.
  - `ARRAY_ITEMS` / `MAP_ITEMS`: encoder — items announced and not started yet; decoder — items left in the current
    block. `SKIPPED_ARRAY_ITEMS` / `SKIPPED_MAP_ITEMS`: decoder, a collection walked with `skipArray`/`skipMap`.
  - Primitive kinds exact (no promotion, as Apache's grammar); fixed size; enum index in range; union index in range.
  - Messages: `Invalid call <call> at '<path>' for the writer schema: expected <what>` (path like `inner.list[2].name`,
    `the root`, or `after the end of the datum`), and `Incomplete datum: expected <what> at <path>, but no more calls
    were made`. Built only on failure; the call names are constants, so a successful call allocates nothing.
- **`ValidatingAvroBinaryEncoder` / `ValidatingAvroBinaryDecoder`** — wrap any `AvroBinaryEncoder`/`AvroBinaryDecoder`,
  check each call, then forward it **unchanged** (an invalid call is never forwarded; a read enum/union index or block
  count is checked once read, as Apache does). `checkDatumComplete()` at the end of the value.
- **Decoder block protocol**: `readArrayStart()` → that many item value calls → `arrayNext()` … until a block of 0;
  `skipArray()` → that many items skipped through the validator → `skipArray()` … until 0 (same for maps, key then
  value). A `skipArray()` is a next block when the skipped collection on top has used up its block, else the start of
  a new (nested) collection — unambiguous. An item that takes no call at all (an array of records without fields) is
  consumed with its block, since no call can open it.

## Wiring (every platform, one function)

- The `validatingAgainst` `expect`/`actual` pair is **deleted** (`Platform.kt`, `Platform.jvm.kt`,
  `Platform.nonJvm.kt`): no platform difference remains. `encodeWithValidation`/`decodeWithValidation`
  (`AvroCodecEntryPoints.kt`) wrap the codec and call `checkDatumComplete()` after the value. **Flag off = one branch**
  (`if (configuration.validateSerialization) { … } else encodeWithBinaryEncoder(…, binaryEncoder)`), read and
  confirmed; no A/B run.
- The Apache entry points `encodeWithApacheEncoder`/`decodeWithApacheDecoder` (public `@InternalAvro4kApi`, signatures
  unchanged) now go through the same `encodeWithValidation`/`decodeWithValidation` around `ApacheEncoderAdapter` /
  `ApacheDecoderAdapter`. **Core main code no longer uses Apache's `ValidatingEncoder`/`ValidatingDecoder` anywhere.**
  Their internal overloads no longer take the Apache writer schema (it was only used for Apache's validator), so
  `AvroObjectContainer`'s datum writer/reader drop their `apacheWriterSchema` field (internal change).
- **Deleted**: `ApacheEncoderOverAbi`, `ApacheDecoderOverAbi`, `AvroBinaryEncoder.validating(Schema)` /
  `AvroBinaryDecoder.validating(Schema)`, the `exactly` helper (`ApacheCodecAdapters.kt` keeps only the two adapters).
  This also removes the decision-log side effect (2026-09-25, M3-12 default 3): with validation on, a fresh
  `AvroSchema` per call was converted to Apache and seeded into the converter caches — there is no conversion on that
  path any more.
- `AvroConfiguration.validateSerialization` KDoc: no longer JVM-only, no Apache class named (doc only). README: the
  "JVM-only" list and the configuration bullet updated.

## Behaviour changes (also in `b8-migration-items.md`)

1. **Exception type — default taken, open to the user's veto:** a validation failure is a
   `kotlinx.serialization.SerializationException` (Apache: `AvroTypeException`, or `ArrayIndexOutOfBoundsException` for
   an out-of-range union index). **No existing test asserted `AvroTypeException` from validation** (grep: the only
   `AvroTypeException` asserts are `DecimalBytesDifferentialTest`, about `BigDecimal` conversion, unrelated), so **no test
   was changed**. Argument that no existing test relied on a validation rejection at all: before this unit every
   validating test ran behind Apache's validator, which throws a non-`SerializationException`; a test expecting avro4k's
   own `SerializationException` could only pass if the validator never fired first.
2. **Stricter than Apache, on purpose** (each would otherwise let corrupt bytes through):
   - one datum per call: the value must be complete (Apache never checks the end: an incomplete datum passes), and a
     call after its end is rejected (Apache's grammar loops to the start of a next datum);
   - encoder: one value per `startItem()` (Apache only counts `startItem()` calls against `setItemCount`, so a dropped
     or duplicated item value passes);
   - decoder: each block read to its end before `arrayNext()`/`mapNext()`, no item beyond the block (Apache counts
     nothing on the decoder side), and the block call must match how the collection is walked (`arrayNext` after
     `readArrayStart`, `skipArray` after `skipArray`);
   - a negative item count (written, or returned by the wrapped decoder) is rejected.
3. **Works on JS and native** (was ignored there).

No existing test changed. `ApacheCodecCallSequenceTest` (the golden Apache call sequences, validation on and off)
passes **unchanged**: the validator forwards every call as is, so the recorder behind the adapter sees exactly the
flag-off sequence, which the goldens already pinned as identical to what Apache's validating codec forwarded.

**`ValidatingAvroBinaryCodecTest`** (`commonTest`, 32): valid datum of every type forwarded byte-identically; empty
arrays/maps; nested unions and collections of unions; records without fields and arrays of them; a recursive record
through its union (with the error path `next.next.v`); wrong primitive kinds (no promotion, fixed vs bytes, enum vs
int); path in messages (`maybe.l`, `list[1].l`); missing field (middle and end); extra call after the datum; union
index out of range (and negative, and on a non-union); wrong branch type and a branch without its index; nested unions
needing every index; enum out of range; fixed length; item count too low/high and negative; item without
`startItem()`, two values for one `startItem()`; unterminated and wrongly-ended array/map; map keys must be strings
(encoder and decoder, read and skipped); decoder: full read with values unchanged, whole datum skipped with
`skip(AvroSchema)`, multi-block arrays and maps read and skipped (including negative-count blocks jumped over by the
wrapped decoder, and nested skipped arrays), a block not read to its end, block-call mismatches (`mapNext` on an array,
`skipArray` after `readArrayStart`, `arrayNext` after `skipArray`), empty collections and arrays of empty records read
and skipped, read kinds/fixed sizes, read enum/union index out of range, skipping with the wrong schema, trailing state
at the end of the datum; through the public API with `validateSerialization = true` on every platform: round trip, and
a custom serializer that makes no call for an `Int` field fails only with validation on (encode and decode).

**`ValidatingCodecDifferentialTest`** (`jvmTest`, 3): the same call sequences fed to Apache's
`ValidatingEncoder`/`ValidatingDecoder` (through the real `ApacheEncoderAdapter`/`ApacheDecoderAdapter`) and to ours,
both over do-nothing / scripted inner codecs, so only validation is compared.
- **Corpus:** 54 schemas — all 52 JSON schemas of `core/src/jvmTest/resources` plus two models (`DiffEveryType`: every
  type, nullable/nested/list-of-records/map-of-lists-of-nullable-records, sealed type, enum, fixed, char;
  `DiffRecursive`). **219 valid encoder and 219 valid decoder sequences**: 3 recorded from encoding and decoding real
  values with avro4k's direct encoder/decoder, the rest generated from each schema with a seeded random walk
  (`Random(20261009)`, 4 per schema: union branches, collection sizes 0-3, and on the decoder side a random split of each
  collection into blocks).
- **Mutations** of every valid sequence at every position: drop a call, duplicate it, swap its kind (int↔long,
  float↔double, string↔bytes, null↔boolean, fixed→bytes/enum, enum→int, index→enum, array↔map start/end/next), and ±1 on
  every union index, enum index, fixed length and item count (written or returned). **6,894 encoder and 6,644 decoder
  mutants.**
- **Result:** every valid sequence accepted by both. **No sequence rejected by Apache and accepted by ours.** Rejected
  by both: 6,186 encoder / 5,084 decoder; accepted by both: 61 / 61 (mutations that stay valid, e.g. another in-range
  enum index). **Rejected only by ours — intended divergences, each checked to be explained:** encoder: incomplete
  datum 254, call after the end of the datum 73, collection item count 320; decoder: 341, 92, 1,066. "After the end of
  the datum" is only accepted as explained if the prefix before the rejected call is a complete valid datum for ours;
  "item count" only if the rejected call is a collection call or what was expected is a collection call/item/count.
  Any other difference fails the test.
- `skipArray`/`skipMap` are left out of the decoder differential: Apache's validating decoder skips the whole collection
  itself (and returns 0) while the ABI hands each block's items back to the caller, so the sequences differ by design.
  They are covered by the common tests, and by `ApacheCodecCallSequenceTest`'s skip golden with validation on.
- "Include the invalid cases the current tests exercise": there are none to include — no existing test triggered a
  validation rejection (see behaviour change 1). All existing tests that run with validation on (every
  `AvroAssertions`-based encoding test, 944 in all) pass under the stricter validator.

## For the orchestrator

- **Veto point:** the exception type (`SerializationException`) and the stricter rules (end of datum, item counting)
  are defaults; Apache's leniencies could be reproduced if the user prefers byte-for-byte Apache parity.
- The `ApacheCodecAdapters.kt` header still says the adapters move to `apache-interop` when core drops Apache (M3-14);
  nothing validation-related is left there to move.
