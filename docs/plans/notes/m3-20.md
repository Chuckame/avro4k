# M3-20 — remove the deprecated okio and stream APIs

**Outcome:** done. **api** (removals only, below). GitHub #318 and #319. No locked decision touched, no remaining public
name or shape changed.
**Commits:** see `git log -- docs/plans/notes/m3-20.md` and the `refactor(core)!: remove the deprecated okio and Java
stream overloads` commit before it.

## What was removed

- `core/src/jvmMain/.../AvroOkioExtensions.kt` (whole file): `Avro.encodeToSink(… okio.BufferedSink)` ×3 shapes,
  `Avro.decodeFromSource(… okio.BufferedSource)` ×3 shapes, and the private `CountingPeekSource`.
- `core/src/jvmTest/.../AvroOkioExtensionsTest.kt` (whole file, 2 tests — it only tested the okio bridge).
- `core/build.gradle.kts`: `jvmMain`'s `implementation(libs.okio)`. `gradle/libs.versions.toml`: the `okio` version and
  library entries (nothing else — no module, `buildSrc`, benchmark, example — used them). Core no longer depends on okio
  on any configuration.
- `core/src/jvmMain/.../AvroJVMExtensions.kt`: the deprecated `Avro.encodeToStream` ×3 and `Avro.decodeFromStream` ×3,
  and their now-unused imports. The file stays: it holds `decodeFromByteBuffer` (not deprecated) and its internal body.
- `core/src/jvmMain/.../AvroSingleObject.kt`: the deprecated `encodeToStream` and `decodeFromStream` members, and
  their now-unused imports.

**Kept (not deprecated, out of scope):** `Avro.decodeFromByteBuffer`, `AvroObjectContainer`'s `OutputStream`/`InputStream`
entry points (`openWriter`, `decodeFromStream`, member and reified), all kotlinx-io overloads.

**Callers outside core:** none. `git grep` for `okio`, `encodeToStream`, `decodeFromStream`, `AvroOkio`,
`AvroJVMExtensions` across benchmark, confluent-kafka-serializer, apache-interop, kotlin-generator, gradle-plugin,
example, bom and buildSrc: only `AvroObjectContainer.decodeFromStream` (kept) in core's tests and the root README.

## Tests

`:core:jvmTest`: **979 → 977**. Removed: `AvroOkioExtensionsTest` — "encodes to an okio sink the same bytes as
encodeToByteArray", "decodes consecutive values from an okio source, consuming exactly their bytes". No test used the
deprecated Java-stream overloads (`Avro.encodeToStream`/`decodeFromStream`, `AvroSingleObject.encodeToStream`/
`decodeFromStream`), so nothing was switched; the two `AvroObjectContainer.decodeFromStream` callers in
`AvroObjectContainerTest` use the kept, non-deprecated API. Common/JS/native test counts unchanged (all removed code and
tests were `jvm*`).

## Docs

- Root `README.md`, "JVM stream encoding": one sentence on bridging okio via `kotlinx-io-okio`
  (`asKotlinxIoRawSource().buffered()` / `asKotlinxIoRawSink().buffered()` — names checked against the 0.9.0 sources);
  fixed the example's `output.asSink()` → `outputStream.asSink()` typo.
- `Migrating-from-v1.md`: the binary-decoding example used `Avro.decodeFromStream`; now a kotlinx-io `Source` loop
  (`decodeFromSource`, all three shapes).
- No KDoc referenced the removed functions; module READMEs did not mention them.
- `b8-migration-items.md` #318/#319 items made exact: all three shapes of each, how to bridge (and flush), what is kept,
  and the one behaviour difference — the removed okio decoding overload consumed exactly the decoded bytes (peek +
  skip), whereas a buffered kotlinx-io source reads ahead, so consecutive values must be decoded from the same `Source`.
  (The removed Java-stream overloads already wrapped with `asSource().buffered()` per call, so they read ahead too: no
  behaviour difference there.)
