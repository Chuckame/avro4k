## What was removed

- `AvroDecoder.decodeValue()` (commonMain, public, `@Deprecated`, `@ExperimentalAvro4kApi`).
- Its core implementations: `AbstractAvroDirectDecoder.decodeValue()` (it always threw
  `UnsupportedOperationException("Direct decoding doesn't support decoding generic values")`) and
  `JsonDefaultDecoder.decodeValue()` (the generic value of a primitive, enum or fixed default).
- The `genericFixedValue(schema, bytes)` `expect`/`actual` (`Platform.kt`, `Platform.jvm.kt`, `Platform.nonJvm.kt`):
  its only caller was `JsonDefaultDecoder.decodeValue()`. The JVM actual built an Apache `GenericData.Fixed`, so core's
  `commonMain` no longer has an Apache-shaped platform seam. With it go the now unused imports (`AvroSchema` in the three
  files, `GenericData` in `Platform.jvm.kt`); `avro4kToApache` stays (used elsewhere in core `jvmMain`).

No other module used it: grep of `confluent-kafka-serializer`, `benchmark`, `kotlin-generator`, `gradle-plugin`,
README and `Migrating-from-v1.md` found nothing (`decodeValue` only appeared in core, apache-interop and `docs/plans/`).

## apache-interop's generic trees

- `AbstractAvroGenericDecoder`'s `abstract override fun decodeValue()` becomes `abstract fun decodeGenericValue(): Any`
  (internal class, so not API). **Renamed**, because keeping the name of the removed public method on a class that
  implements `AvroDecoder` would read as an override of it. Its four implementations (`AvroValueGenericDecoder`,
  `MapGenericDecoder`, `ArrayGenericDecoder`, `RecordGenericDecoder`) and the base class's `decode*` table are otherwise
  unchanged.
- **The default route** (`RecordGenericDecoder`, a reader field missing from the writer record):
  `decodeSerializableValue` already hands a default as a whole to `avro.defaultValueDecoder(step)` (unchanged); the
  primitive `decode*` methods of the base class read `decodeGenericValue()`, which for a default used to be
  `avro.defaultValueDecoder(step).decodeValue()`. It is now a private `AvroDecoder.decodeGenericDefaultValue()` in
  `RecordGenericDecoder.kt`: **the same table `JsonDefaultDecoder.decodeValue()` had, moved into apache-interop and fed
  by the typed public methods of the decoder `defaultValueDecoder` returns**:

  | default's schema (`currentWriterSchema`, never a union there) | generic value |
  |---|---|
  | boolean / int / long / float / double | `decodeBoolean()` / `decodeInt()` / `decodeLong()` / `decodeFloat()` / `decodeDouble()` |
  | string, enum | `decodeString()` |
  | bytes | `decodeBytes()` |
  | fixed | `GenericData.Fixed(schema.toApacheSchema(), decodeFixed())` |
  | anything else | `UnsupportedOperationException`, same message |

  Each typed call on the matching schema type runs exactly the expression the old table ran (`primitive.boolean`,
  `intValue()` with its char case, `primitive.long`, `primitive.float`, `primitive.double`, `primitive.content`,
  `bytesValue()`), and `toApacheSchema()` is the same identity-cached `avro4kToApache` that `genericFixedValue` called,
  on the same (reader-schema branch) instance, so the cache hits as before. The `JsonNull` check before it, and its
  `DecodedNullError(descriptor, index)`, are unchanged.

### Why this route and not the two others

- **Decode the default with the field's own deserializer / the typed method of the default decoder** (override each
  `decode*` of `RecordGenericDecoder` to call `defaultValueDecoder(step).decodeX()`, as `RecordDirectDecoder` does).
  Rejected: values agree, but **not** the failures — a mismatch would throw `JsonDefaultDecoder`'s
  `unsupportedWriterTypeError` instead of the generic tree's `BadDecodedValueError`, with different messages, and
  `beginStructure` on an inline default element would start succeeding where it threw. Not "identical".
- **Turn the json default into a generic value inside apache-interop** (re-implement the conversion on the
  `JsonElement`). Rejected: it would duplicate core's `internal` default handling (`resolveDefaultBranch`, the char code,
  the 0-255 bytes mapping, fixed padding), or need them exposed as `@InternalAvro4kApi`.
- **Chosen:** a hybrid — the generic value is built in apache-interop (where Apache types belong), but every leaf comes
  from core's own default decoder through the public `AvroDecoder` methods, so no conversion rule is duplicated, nothing
  new is exposed, and both values and failures are identical by construction (the base class's table still converts
  the generic value, as before).

**Per-value boundary / structural equality:** no new schema conversion (the one `toApacheSchema()` replaces the
identical `avro4kToApache` call that `genericFixedValue` made, per fixed default read); the only comparison in the
touched runtime code is a `when` on the `AvroSchema.Type` enum.

## The documented replacement: `AnySerializer` — gaps for the user

The orchestrator relayed (2026-10-09) that the replacement to document is `decoder.decodeSerializableValue(AnySerializer())`
(plus `currentWriterSchema` + the typed `decode*` for the simple cases), and no new reference to `decodeResolving*`.
Done in `AvroDecoder`'s KDoc and in `b8-migration-items.md` (README never mentioned `decodeValue`). Checked with a
throwaway probe (not committed), it is **not a drop-in for every case `decodeValue()` covered**:

1. **`AnySerializer` itself is `@InternalAvro4kApi`** (as is `AbstractAnySerializer`), so it is not in `core.api` —
   documenting it as the user-facing replacement contradicts its marker. Users can also reach it without naming it, as
   the contextual serializer of `Any` (`serializersModule.serializer<Any>()`, from `Avro.Default`'s module).
2. **It only works on the binary decoder**: `AbstractAnySerializer.deserialize` casts the decoder to
   `AbstractAvroDirectDecoder`. On a **missing field's default** (`JsonDefaultDecoder`) and through
   **`decodeFromGenericData`** (apache-interop's generic decoders) it throws `ClassCastException`. `decodeValue()`
   worked on exactly those two (and always threw on the binary decoder), so for code that used `decodeValue()` where it
   actually worked, `AnySerializer` currently fails.
3. **Different value types** (expected, as documented): a fixed decodes as `ByteArray` (was `GenericData.Fixed` on the
   JVM), an enum as `String`, a record or map as `Map<String, Any?>`, logical types per `AvroConfiguration.logicalTypes`.

Not worked around here, as asked. Fixing 2 means `AnySerializer` reading the schema through the public
`AvroDecoder.currentWriterSchema` (and the `Avro` configuration through some other route) instead of casting; 1 is a
public-API decision.
