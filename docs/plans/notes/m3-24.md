## Step 1 — union resolution in the generic decoder

**Where:** `apache-interop/…/internal/decoder/generic/AbstractAvroGenericDecoder.kt`, one place:
`currentWriterSchema` (final) returns `currentAvroSchema` unless it is a `UnionSchema`, then `resolveUnion(union)`, which
calls `union.branchOfOrNull(currentGenericValueOrNull())` and throws if `null`. `currentGenericValueOrNull()` is a new
abstract method: the value at the current position **without consuming it** (a serializer may read the schema before
decoding).

**The rule** (`UnionSchema.branchOfOrNull(value)`, internal, same file), Apache `GenericData.resolveUnion`-like:

| generic value | branch |
|---|---|
| `null` | the `null` branch |
| `GenericArray` (checked first: it is a `GenericContainer` too, of an unnamed array schema) | array |
| other `GenericContainer` (`IndexedRecord`, `GenericFixed`, `GenericEnumSymbol`) | `union.getIndexOrNull(value.schema.fullName)`: the union's own full-name index, which also holds aliases (a superset of Apache, which ignores aliases) |
| `Map` | map |
| other `Collection` | array |
| `CharSequence` | string |
| `ByteBuffer`, `ByteArray` | bytes |
| `Int` / `Long` / `Float` / `Double` / `Boolean` | that type |
| no exact match | **the only non-null branch** if there is exactly one (every `["null", X]` keeps today's behaviour, e.g. an `Int` for `["null", long]`), else `null` |

When `null`: `SerializationException("The generic value '<v>' of type <class> matches no branch of the union <json>")`,
thrown **only when the schema is read** (a primitive `decode*` that never reads it still works as before). Branch lookup
by `type ===` (enum identity) or the full-name string map; no `AvroSchema`/`Field` equality.

Per decoder:
- `AvroValueGenericDecoder`: its value.
- `RecordGenericDecoder`: `record.get(writerFieldIndex)`; for a **missing field's default**, `resolveUnion` is overridden to
  return `avro.defaultValueDecoder(step).currentWriterSchema` — the branch the default's json picks, the same one its own
  decoder decodes with (a cold path; one `JsonDefaultDecoder` per read).
- Map: the current entry's value (a key's schema is `string`, never a union). The map decoder became
  `AbstractMapLikeGenericDecoder` + `MapGenericDecoder`, to share it with the new `RecordAsMapGenericDecoder` (below).
- Array: elements are now read from the iterator **once, on demand** (`peekItem`), so the schema can be read before
  `decodeNotNullMark`/`decode*`; decoding the element or its `null` (`decodeNull` now overridden) moves on. Before, a
  non-null element whose schema was a union could not be peeked.
- **The map/array `["null", …]` special cases are gone**: `beginStructure` builds the map/array decoder with
  `structureSchemaOf(value)`: the branch holding the value when the position's schema is a union, **else the union
  itself** (lenient: only reading an element schema then fails with `Not a map`/`Not an array`, as before; m3-19's
  "a decode that never reads the schema cannot start failing" holds).
- Polymorphic: unchanged (it needs the union to find the serial name; a `GenericContainer` already brings its own schema).

Also needed for `AnySerializer` from generic data (it decodes a record with a map deserializer and an enum as a string,
as from bytes): `beginStructure(MAP)` accepts an `IndexedRecord` (`RecordAsMapGenericDecoder`, field name → value, each
value with its field's schema, like core's `RecordAsMapDirectDecoder`), and `decodeString()` accepts a
`GenericEnumSymbol` (its `BadDecodedValueError` lists it among the expected types — the only message change, in
apache-interop, on a path that failed before).

### `AnySerializer` on any avro4k decoder

`AbstractAnySerializer.deserialize` cast the decoder to `AbstractAvroDirectDecoder` for two things: the writer schema and
the `Avro` configuration (logical types). Now: `decoder as AvroDecoder` (a non-Avro decoder still gets a
`ClassCastException`, as before), the schema from the public `currentWriterSchema`, and the configuration — only on a miss
of the decoding cache — through a new **`@InternalAvro4kApi public interface AvroFormatDecoder : AvroDecoder { val avro:
Avro }`** (`core/…/internal/decoder/AvroFormatDecoder.kt`), implemented by `AbstractAvroDirectDecoder` (its `internal val
avro` becomes `final override val avro`), `JsonDefaultDecoder` (`private` → `override`) and apache-interop's
`AbstractAvroGenericDecoder` (`internal abstract` → `abstract override`). Hidden from `core.api` (non-public marker).
**Why an interface:** `AvroDecoder` exposes no configuration, and apache-interop's decoders live in another module, so
core cannot name them; every other route either duplicates the configuration, or allocates a configured wrapper per
value. A decoder that is an `AvroDecoder` but not avro4k's gets a `SerializationException` naming it (none exists).
**Binary path unchanged:** `currentWriterSchema` is `AbstractAvroDirectDecoder`'s final getter of `currentAvroSchema`,
and the configuration is the same `avro.configuration`; the mock-based `AnySerializerTest` passes unchanged (it stubs
both schemas and `avro`). What changes: on a missing field's default — from bytes too — it now works instead of a
`ClassCastException` (asked by the spec).

## The amendment — `AnySerializer` is `@ExperimentalAvro4kApi`

Relayed user decision (2026-10-10): it is the documented replacement of `decodeValue()`. **`AbstractAnySerializer` is
made experimental too**, not kept internal: it holds what `AnySerializer`'s users see — `nullable` (recommended in its
KDoc) and the protected decoding hooks (`preResolveDeserializationStrategy`, `resolve{Array,Map,Enum,Fixed,Record}DeserializationStrategy`)
that a subclass overrides; with it internal-marked, `AnySerializer().nullable` or an override would need the internal
opt-in. It still cannot be extended directly (its constructor stays `internal`, so not in the dump). The JVM and non-JVM
`actual`s and their encoding hook `inferSerializationStrategyFromNonSerializableType` are experimental as well. KDoc of
`AnySerializer` now documents decoding any writer schema (logical types per `AvroConfiguration.logicalTypes`, then by
type) on every avro4k decoder; `b8-migration-items.md`'s `decodeValue()` entry no longer says it is internal.

**The "experimental opt-in only" check:** every module compiles with `-opt-in=…InternalAvro4kApi` (both conventions,
tests included), so a compile test cannot prove it without a new compilation. Instead a `jvmTest` checks the compiled
markers: `AnySerializer` carries `@ExperimentalAvro4kApi`, and neither it, `AbstractAnySerializer` nor any of their
public/protected methods (property annotation holders included) carries `@InternalAvro4kApi` (the markers have runtime
retention). It fails on the code before the amendment.

`core.api` gained (amendment commit):

## Step 2 — `decodeResolving*` removed

The 11 `decodeResolvingAny` call sites (`AvroDurationSerializer`, `KotlinUuidSerializer`, `KotlinInstantSerializer`,
`UUIDSerializer`, `BigIntegerSerializer`, `BigDecimalSerializer`, `LocalDateSerializer`, `LocalTimeSerializer`,
`LocalDateTimeSerializer`, `InstantSerializer`, `InstantToMicroSerializer`) read `currentWriterSchema` once and `when` on
its type (and logical type / fixed size), each `null`-returning resolver branch becoming a `throw` of the **same** error
the old `error` lambda built (`UnexpectedDecodeSchemaError(...)` with the same arguments, which formats
`currentWriterSchema` — the same schema it formatted before; small private `*SchemaError()` helpers where it repeats).
`AvroDurationSerializer` keeps its `else -> throw SerializationException("Expected the duration logical type … but had
${type}")`. For a non-union schema (the only kind any decoder now hands a serializer) every value and every exception is
identical; all existing tests pass unchanged.

Deleted from `AvroDecoder.kt`: the 9 `decodeResolving*` inline functions, the 9 `*ValueDecoder` fun interfaces and the
`@PublishedApi internal findValueDecoder`. KDoc: `AvroDecoder`'s list replaced by the `when (currentWriterSchema.type)`
pattern (with an example) and `AnySerializer`; `AvroSerializer.deserializeAvro` no longer recommends them. No other
user (grep of every module, README, migration guide).

**Mutation check:** with step 1's resolution disabled (`currentWriterSchema` returning the raw schema) after the
rewrite, **all 17 nullable-logical-type round trips and the int-for-long fallback fail** (`For Instant, expected type
one of [LONG], but had writer schema ["null",…]`, `…but had UNION` for durations), 39/56 of the new tests in all;
restored, all pass. The dependency the decision log names is covered.

`core.api` (step 2): **−49 lines, removals only** — `AnyValueDecoder` … `ShortValueDecoder` (9 interfaces) and, in
`AvroDecoderKt`, the 9 `decodeResolving*` plus `findValueDecoder` (it was in the dump as `@PublishedApi`).

## `AvroDecoder.currentWriterSchema: ResolvedSchema` (user request, 2026-10-10, mid-unit)

"As `currentWriterSchema` should never return a union, make it return `ResolvedSchema`." Done as its own commit after
step 3. `core.api`: `getCurrentWriterSchema ()…AvroSchema;` → `()…ResolvedSchema;` (one changed line; a binary change
for compiled callers, source-compatible for Kotlin). Per decoder:
- **Binary** (`AbstractAvroDirectDecoder`): the getter calls `decodeAndResolveUnion()` (idempotent: reads the union index
  only if `currentAvroSchema` is still a union) then returns `currentAvroSchema as ResolvedSchema`. The only state where
  it changes anything is a decoder handed out unresolved — `decodeInlineElement` on a union field, read before any
  decode — where it used to return the union (and a serializer then picked a branch *without reading the index*, i.e.
  misread the bytes). Cost per read: one type comparison and a check-cast. Internal `unsupportedWriterTypeError` now
  formats the binary decoder's raw `currentAvroSchema` (not the getter), so building an error never reads an index and
  every message stays byte-identical.
- **Default** (`JsonDefaultDecoder`): `resolveDefaultBranch` returns `ResolvedSchema` (an exhaustive `when` over the sealed
  `AvroSchema`; it already threw when no branch fits).
- **Generic** (apache-interop): `when (currentAvroSchema) { is ResolvedSchema -> it; is UnionSchema -> resolveUnion(it) }`;
  `resolveUnion`/`branchOfOrNull` typed `ResolvedSchema`.
- `AbstractAnySerializer`'s `UNION` branch is now unreachable through the decoder (kept: the `when` is on the type enum);
  its public hooks keep their `AvroSchema` parameters (no reshape).

Tests: `AnySerializerTest` "should throw error when serializing union schema" (a mock stubbing `currentWriterSchema` with
a union, which the type no longer allows) is **replaced** by "never sees a union: the binary decoder resolves the branch
of a union value handed out by decodeInlineElement" (real bytes of a `["null", "long"]` field read with
`AnySerializer().deserialize(decodeInlineElement(…))` → `42L`; mutation-checked: without the getter's resolution it fails
with a `ClassCastException`, and on the code before this commit `AnySerializer` threw its "union" error). The mock helper
`stubWriterSchemas` and the bridge's `stubWriterSchema` cast to `ResolvedSchema`. Count unchanged (973).

## Open design question from the user: letting users resolve a union themselves ("pluggable architecture")

Not implemented (new public API; answered in the report). Today the resolution is decoder-owned and fixed per source:
the written index (binary), the default's json, the generic value's kind. Options, for a decision:
1. **A union-branch hook on the decoder**: e.g. an experimental `AvroDecoder.decodeUnionBranch(): ResolvedSchema`-style
   call is not needed for the binary format (the index is data, not a choice); a hook only makes sense where the
   resolution is *inferred* — generic data (and future JSON/other formats). There, a `GenericUnionResolver` fun
   interface (`(union: UnionSchema, value: Any?) -> ResolvedSchema?`) set on an apache-interop entry point (an optional
   parameter of `decodeFromGenericData`, or an `Avro`-level setting) would let users plug Apache's
   `GenericData.resolveUnion` (with logical-type conversions), aliases-off matching, or numeric promotions, falling back
   to the built-in rule. Cheapest, contained to apache-interop, no core change.
2. **Reader-side choice in a serializer**: a serializer that wants the raw union could get it through a separate,
   explicit accessor (e.g. `AvroDecoder.currentWriterUnion: UnionSchema?`, the union the current branch was resolved
   from), keeping `currentWriterSchema` a `ResolvedSchema`. Useful for serializers that need to know the alternatives
   (e.g. to map branch names to subtypes) without re-introducing resolution in every serializer.
3. **Polymorphic / custom-format decoders**: the existing `AbstractPolymorphicDecoder.tryFindSerialNameForUnion` is
   already a per-decoder resolution strategy; a public, format-neutral `UnionResolver` abstraction in core would serve a
   future third decoder family (JSON encoding of Avro), but is premature before such a format exists.
Recommendation: (1) if a generic-data user asks; (2) only with a concrete serializer need. Both are additive, experimental.

## For the user

- **New `@InternalAvro4kApi` symbol** `AvroFormatDecoder` (above): hidden from `core.api`, but it is a public Kotlin
  interface; the brief said "no public API change" for `AnySerializer`'s fix, and there is no route to the configuration
  from apache-interop's decoders without one (M3-19/M3-23 precedent: internal-API additions for apache-interop, listed).
- `AbstractAnySerializer` is in `core.api` as experimental, by the amendment's own criterion (its members are hooks
  users override); revert to internal-marked only if the hooks should not be public.
- Perf: on the binary path, `AnySerializer` per value now does an interface check-cast + `currentWriterSchema` instead
  of a class check-cast + `currentAvroSchema` (the configuration is read only on a cache miss); the built-in logical-type
  serializers no longer allocate a capturing lambda per value off the JVM (measured in M5, no A/B here).
