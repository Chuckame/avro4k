## What changed

**The two members** (`core/…/AvroDecoder.kt`, `core/…/AvroEncoder.kt`): `public val avro: Avro`, first member of each
interface, KDoc "the [Avro] instance this decoder decodes with / encoder encodes with: a custom serializer reads its
`configuration` (e.g. the `logicalTypes`) and its `serializersModule` from it, as with kotlinx-serialization's
`JsonDecoder.json` / `JsonEncoder.json`". **Not** `@ExperimentalAvro4kApi` (the spec says public; kotlinx's `json` is
stable), unlike the interfaces' other members — see "For the user".

**Every implementation** (found by grepping for `AvroDecoder`/`AvroEncoder` supertypes, their abstract bases' subclasses,
and `mockk<…>` fakes in every module, tests and benchmark included):

| Class (all `internal` or `@InternalAvro4kApi`) | Before | After |
|---|---|---|
| core `AbstractAvroDirectDecoder` (all binary decoders: value, record, record-as-map, array, map) | `final override val avro` of `AvroFormatDecoder` | same property, now overriding `AvroDecoder.avro` |
| core `JsonDefaultDecoder` (a missing field's default; its composite decoders are `CompositeDecoder`s, not `AvroDecoder`s) | `override val avro` of `AvroFormatDecoder` | overrides `AvroDecoder.avro` |
| apache-interop `AbstractAvroGenericDecoder` (value, record, map, record-as-map, array) | `abstract override val avro` of `AvroFormatDecoder` | overrides `AvroDecoder.avro`; subclasses' `override val avro` unchanged |
| core `AbstractAvroEncoder` (`@InternalAvro4kApi`, public) | — | inherits the abstract member, nothing redeclared |
| core `AbstractAvroDirectEncoder` (binary value, record ×3, array, map encoders) | `protected val avro` (constructor) | `override val avro` — public on an `internal sealed` class, so nothing exposed |
| apache-interop `AbstractAvroGenericEncoder` (value, record ×3, array, map) | `abstract val avro` | `abstract override val avro`; subclasses' `override val avro` unchanged |

No clash: every existing `avro` already had type `Avro` and simply became the override; the only visibility change is
the direct encoder's `protected` → public override, on an internal class. The polymorphic encoders/decoders
(`PolymorphicDirectEncoder`, core's `PolymorphicDecoder`, apache-interop's `PolymorphicEncoder`/`PolymorphicGenericDecoder`)
and `ReorderingCompositeEncoder`/its `BufferingInlineEncoder` are plain kotlinx `Encoder`/`Decoder`/`Composite*`, not
`AvroEncoder`/`AvroDecoder`: untouched. No hand-written fake of either interface exists in the tests (only
`mockk<AvroDecoder>()`/`mockk<AvroEncoder>()` in `CustomAvroSerializerTest`, which never read `avro`, and the
`mockk<AbstractAvroDirectDecoder>` of `AnySerializerTest`, which already stubbed `avro`).

**`AvroFormatDecoder` deleted** (`core/…/internal/decoder/AvroFormatDecoder.kt`). `AbstractAnySerializer.deserialize`
reads `decoder.avro.configuration` (still only on a miss of the decoding cache) after the unchanged `decoder as
AvroDecoder`; its private `avroConfiguration()` helper and its `SerializationException` are gone. KDoc of `deserialize`
says where the logical types come from and that a non-`AvroDecoder` fails with a `ClassCastException`.

**Failure on a non-avro4k decoder, checked:** a `Decoder` that is not an `AvroDecoder` gets the same
`ClassCastException` as before (from `decoder as AvroDecoder`, message `… cannot be cast to class
com.github.avrokotlin.avro4k.AvroDecoder …`) — now pinned by a test. The only behaviour change: a **third-party
`AvroDecoder`** (not avro4k's) used to get M3-24's `SerializationException("… only decodes with avro4k's own decoders, not
with …")`; it now decodes, with the logical types of its own `avro` (it must implement `avro` anyway).

**Migration:** `b8-migration-items.md`, an item after the `ResolvedSchema` one (breaking only for third-party
implementations of the two interfaces; what to implement; `AnySerializer` on such a decoder). `Migrating-from-v1.md`
untouched: M3-24 changed it only for the generic data undeprecation, never for the decoder interface (its
`currentWriterSchema`/`decodeResolving*` changes went to `b8-migration-items.md` only), so this follows the same split.

## What was rejected, and why

- **`@ExperimentalAvro4kApi` on the two members**: the spec asks for a public member like `JsonDecoder.json`, which is
  stable in kotlinx-serialization; the `Avro` type it returns is stable API already. Left for the user (below).
- **Redeclaring `abstract override val avro` on `AbstractAvroEncoder`**: it inherits the abstract member; redeclaring
  adds nothing (the class is `@InternalAvro4kApi`, so not in the dump either way).
- **Wrapping the `ClassCastException` into a `SerializationException`** for a non-`AvroDecoder`: a message change the
  spec does not ask for ("fails as before").
- **Touching `Migrating-from-v1.md`**: see Migration above.

## For the user

- The two members are **stable** public API (not experimental), as the spec's `JsonDecoder.json` analogy. If they should
  be `@ExperimentalAvro4kApi` like `currentWriterSchema`, it is a one-line annotation each, no `.api` change.
- Perf: none on the hot path. `AnySerializer` reads `decoder.avro` instead of an interface check-cast + the same
  property, only on a decoding-cache miss.
