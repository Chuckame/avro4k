# M5-04 — Polymorphic values decoded without per-value allocation

**Outcome:** implemented, tests green on JVM, JS (Node) and macosArm64. Not measured: the orchestrator measures it in
the read A/B. Internal code only: no API change (`core/api`, klib included, and `apache-interop/api` are clean).

**Branch** `v3/polymorphic-decode-reuse`, base `5504c87b`, one commit (code, tests, this note).

## What changed and why

Before, every polymorphic value built four objects (`benchmark/README.md`, "objects reused per nesting level": the
`readPolymorphic` regression):
- a `PolymorphicDecoder` (32 B), built by the parent's `beginStructure`;
- a `Pair<String, AvroSchema>` (24 B), the serial name and the branch it was found for;
- an `AvroValueDirectDecoder` (48 B) for the value;
- the subclass's record decoder (64 B exact), in that new value decoder's empty slot. An enum subclass has none.

Now none of them is built per value.

Files:
- `core/.../internal/decoder/AbstractPolymorphicDecoder.kt` (public `@InternalAvro4kApi`, out of the dumps):
  - `tryFindSerialName(map, schema)` and the abstract `tryFindSerialNameForUnion` return `String?`; the branch found is
    recorded in `protected var chosenSchema: AvroSchema?`, set on a match only, so in `firstNotNullOfOrNull` the first
    match is still the one kept. No `Pair`.
  - `descriptor`/`schema` are `private var`s (still constructor parameters), with `internal open fun reset(descriptor,
    schema)`, which also clears `chosenSchema`.
  - the lookup moved from a private method into `internal open fun findSerialName(descriptor, schema)`, the hook the
    direct decoder overrides to remember names. `decodeString` and its error message are unchanged.
  - `decodeSerializableValue` before any serial name was found throws an `IllegalStateException` (was the `lateinit`'s
    `UninitializedPropertyAccessException`), so a reused decoder never decodes with its previous value's branch.
- `core/.../internal/decoder/JsonDefaultDecoder.kt`, `apache-interop/.../PolymorphicGenericDecoder.kt`: the union
  override returns `String?`; otherwise unchanged.
- `core/.../internal/decoder/direct/PolymorphicDecoder.kt` (new file; the class moved out of
  `AbstractAvroDirectDecoder.kt`, now `internal`, same name because its name appears in the indexed-access error
  message): the slot, the value decoder and the memo, below.
- `core/.../internal/decoder/direct/AbstractAvroDirectDecoder.kt`: a fifth slot, `polymorphicDecoder`, and its helper.
- `core/.../internal/decoder/direct/AvroValueDirectDecoder.kt`: `reset(writerSchema)` (schema, then `beginReuse()`).

### The slot and the busy guard

```kotlin
private fun polymorphicDecoder(descriptor: SerialDescriptor, schema: AvroSchema): PolymorphicDecoder {
    val kept = polymorphicDecoder
    if (kept != null && !kept.inUse) {
        kept.reset(descriptor, schema)
        return kept
    }
    val decoder = PolymorphicDecoder(avro, descriptor, schema, binaryDecoder)
    if (kept == null) polymorphicDecoder = decoder
    return decoder
}
```

The same shape as the four other slots: a busy kept decoder is left in its slot and the value gets a fresh decoder.
`inUse` is set by the constructor and `reset`, cleared by the polymorphic decoder's own `endStructure` (kotlinx's
`AbstractPolymorphicSerializer` ends its structure through `decodeStructure`, without `try/finally`, as M5-02 found for
the others). The record and block decoders pack their busy state into a position index; the polymorphic decoder has no
index, so it has a `Boolean`, which costs nothing (layout below: 88 B with or without it).

The polymorphic decoder keeps its `AvroValueDirectDecoder` and resets it for each value (`newDecoder`, a public name
kept as is). The value decoder's own slots then keep the subclass's record decoder: a list of one subclass hits its
exact-record memo; Good/Bad partners alternating miss it and fall through to `RecordResolver`'s identity cache, which
allocates nothing on a hit. Nothing guards the value decoder: it is only used between `decodeString` and the end of its
polymorphic decoder's value, and a polymorphic decoder begun again while in use is never reused (the guard above).

### The memo

On the direct `PolymorphicDecoder`, four entries of `(descriptor, branch, serialName)` in twelve fields (three arrays
would be three more objects per decoder):

```kotlin
override fun findSerialName(descriptor: SerialDescriptor, schema: AvroSchema): String? {
    val branch = if (schema.isUnion) readBranch(schema) else schema
    val serialName = rememberedSerialName(descriptor, branch) ?: return findAndRememberSerialName(descriptor, branch)
    chosenSchema = branch
    return serialName
}
// rememberedSerialName: if (descriptor0 === descriptor && branch0 === branch) return serialName0 … ×4
```

- **Identity only**, both halves `===`. A descriptor or branch equal but another instance is looked up, as before.
- **Pure.** The serial name depends only on the descriptor and the branch, the `Avro` instance being the call's.
- **Per-call state**, like the decoder: no sharing between calls.
- **A union is read first**, so entries are by branch. `tryFindSerialNameForUnion` on the direct decoder is now
  unreachable (no `UnionSchema` branch is a union: `types: List<ResolvedSchema>`); it is kept, correct, for the abstract
  contract.
- **Overflow:** once four entries are taken, each new name replaces the last entry. The first three stay, so values
  cycling through five or more subclasses still hit for three of them; replacing the oldest would miss on every value
  of such a cycle.
- **Misses are not remembered.** An unknown subclass throws exactly as before.

### Where the union path is reached

The parent resolves a union before it calls the deserializer (`AbstractAvroDirectDecoder.decodeSerializableValue` and
`decodeNotNullMark` both call `decodeAndResolveUnion`), so on the direct path the polymorphic decoder is nearly always
given the branch already: a non-nullable polymorphic field written as a union is resolved by its record decoder. The
polymorphic decoder reads the union itself only when a serializer hands a deserializer the decoder of
`decodeInlineElement`, which a test now does. `JsonDefaultDecoder` also resolves before (`resolveDefaultBranch`), so
`firstNotNullOfOrNull` really runs only in `apache-interop`'s generic decoder.

## Tests added (11, `commonTest`, run on JVM, JS, native)

`core/src/commonTest/kotlin/com/github/avrokotlin/avro4k/encoding/PolymorphicDecoderReuseTest.kt` (new). Round trips
decode with `Avro` and `Avro { validateSerialization = true }`; the protocol-breaking serializers with `Avro` only.
1. `records objects and enums alternating in one list decode`: data classes, a `data object` and an enum of one sealed
   interface, alternating in a list and as a last field, then lists of those records.
2. `nullable polymorphic fields decode`: two nullable polymorphic fields per record, nulls and values interleaved.
3. `a union read by the polymorphic decoder itself decodes`: non-nullable polymorphic fields written as a union, read
   by the generated serializer and by one that hands `decodeInlineElement`'s decoder to the sealed serializer, so that
   the polymorphic decoder reads the branch index itself (and remembers names by branch across the list).
4. `an unknown subclass fails with the same message`: the full message, at the root and as the second value of a list
   after a known subclass was remembered.
5. `polymorphic default values decode`: a record default, an enum default and another record default, plus an
   implicit `null`, on three records of a list (`JsonDefaultDecoder`'s polymorphic decoder).
6. `polymorphic values nested in polymorphic values decode`: an expression tree, polymorphic subclasses holding
   polymorphic fields and lists, six levels deep.
7. `more subclasses than the decoder remembers alternate in one list`: six subclasses of different shapes, cycled,
   reversed, then in an irregular order.
8. `two polymorphic types reading the same writer schemas decode`: four writer schema instances read by fields of two
   sealed types whose subclasses give them different serial names (one by name, the other by `@AvroAlias`); the second
   type's fields come in reverse order, so each remembered entry is the one matched.
9. `a serializer beginning a second polymorphic value before ending the first decodes both`: both serial names found
   before either value, at the root, as a record field between polymorphic fields, and as list items.
10. `a serializer that never ends its polymorphic values decodes`: as fields and list items, with ordinary siblings after.
11. `successive polymorphic values are decoded by one decoder`: the polymorphic decoder and the value decoder of a list's
    items are one instance each; when not ended, each value gets a new polymorphic decoder.

**Nested polymorphic values do not reach the busy path**, contrary to what the decomposition listed: a polymorphic
value inside a subclass is begun by that subclass's record decoder, at another level, never on the polymorphic decoder
in use. Test 6 covers nesting; tests 9–11 cover the busy path.

`apache-interop`'s generic polymorphic tests pass unchanged (575 tests, green).

`PolymorphicDecoder` after: base `avro`, `descriptor`, `schema`, `chosenSchema` at 12–24 (unchanged), `inUse` at 28
(1 B and 3 of padding), `binaryDecoder` 32, `valueDecoder` 36, the twelve memo fields 40–84. Without `inUse` it would
still be 88 (84 rounded up).

**Four existing decoders grow by 8 B, which the brief asked to avoid if possible.** The base class gains one reference
(4 B) for the fifth slot; the exact record, map block, value and record-as-map decoders had no padding left, so they
round up by a word. The general record and array block decoders absorb it. I found no way to avoid it without removing
a field another unit relies on:
- the two collection-state ints in the base cannot share a word (the total needs the full range);
- sharing a slot with another kind (the general record or the map block decoder) would thrash on records holding both,
  `Client` among them (`partner` and `map`), allocating per value again;
- holding the polymorphic decoder once per call rather than per level would allocate for every nested polymorphic value;
- shrinking the exact record decoder (its memo keys inside a resolved-workflow object) changes the previous unit's hot
  path.
It is per decoder in the call's tree, not per value: +8 to +32 B per call on most rows (predictions below).

Native and JS, estimated: every direct decoder gains one reference (≈ +8 B on Kotlin/Native, one property on JS); the
polymorphic decoder grows from 6 to 19 fields (≈ 56 → ≈ 160 B on Native) but is built once per call per level; per
value, a polymorphic decoder, a `Pair`, a value decoder and a record decoder are no longer built (≈ 56 + 24 + 80 + 96 B
on Native), which neither platform's lack of escape analysis can hide.

## Predicted effect (measured in the read A/B)

Escape-analysis-off allocation rows (`-XX:-DoEscapeAnalysis`), JDK 21, from the layouts above, counted on the head of
the last allocation run (`90ca45cf`, `benchmark/README.md`). Decoder objects only; nothing else in the read path
changes (same codec calls, same kotlinx builders; the name lookup allocated nothing on a hit).

Two parts:
- **Per value:** −168 B per polymorphic value of a record or object subclass (decoder 32 + `Pair` 24 + value decoder
  48 + exact record decoder 64), −104 B per enum subclass value (no record decoder).
- **Per call:** +8 B per exact record, map block, value and record-as-map decoder in the call's tree, and, at a level
  that decodes polymorphic values, the kept polymorphic decoder (88) and value decoder (56), plus the kept subclass
  record decoder (72) when a record subclass is decoded.

## Deviations and things to review

- **Four decoders grow by 8 B** (exact record, map block, value, record-as-map), from the fifth slot; see the layouts.
  This moves rows that were expected not to move: +8 to +32 B per call on every avro4k read row.
- **The union path of the direct decoder is reached only through `decodeInlineElement`**, not by a non-nullable
  polymorphic field written as a union (its record decoder resolves the union first). Its `tryFindSerialNameForUnion`
  override is unreachable.
- **Nested polymorphic values are not the busy fallback**; the busy path is covered by protocol-breaking serializers.
- **`findSerialName` and `reset` are new `internal open` members** of the public `@InternalAvro4kApi`
  `AbstractPolymorphicDecoder`; `chosenSchema` became `protected var` and nullable. None appears in a dump.
- **Asking a polymorphic decoder for its value before its serial name** fails with `IllegalStateException`, not
  `UninitializedPropertyAccessException` (same reason as M5-02: a reused decoder must fail as a new one does, and the
  `lateinit` cannot be unset). No kotlinx serializer does it.
- **`PolymorphicDecoder` keeps its name**, now `internal` in its own file: its class name appears in the
  "does not support indexed access" message.
- **The memo replaces its last entry on overflow**, not the oldest, for the reason given above.
